# 2026-06-22 TIL - GNN과 LangGraph

## 오늘 배운 내용

### 1. 그래프 신경망, GNN

- 그래프 신경망은 노드와 엣지로 구성된 그래프 구조 데이터를 처리하는 딥러닝 모델이다.
- 기존 딥러닝 모델은 이미지나 표처럼 정해진 순서와 벡터 형태를 가진 유클리드 데이터를 주로 다룬다.
- 그래프 데이터는 노드 순서가 고정되어 있지 않고 관계 구조가 복잡하기 때문에 그대로 처리하기 어렵다.
- 그래프에서 노드는 개체를, 간선은 개체 간 관계를 나타낸다.
- 그래프의 종류에는 무방향 그래프, 방향 그래프, 가중치 그래프가 있다.
- 그래프를 컴퓨터에서 표현하는 방법으로는 인접행렬과 차수행렬이 있다.
- 그래프 임베딩은 그래프 구조를 낮은 차원의 벡터로 표현하려는 방법이다.
- 하지만 모든 노드 임베딩을 저장해야 하므로 비용이 크고, 동적인 그래프에는 약하다는 한계가 있다.
- GNN의 핵심 아이디어는 "노드는 연결된 이웃 노드들의 정보로 표현될 수 있다"는 것이다.
- GNN은 이웃 노드의 정보를 모으는 Aggregation, 그래프 전체 표현을 만드는 Readout, 목적에 맞는 예측을 수행하는 Neural Network 구조로 구성된다.
- GNN은 노드 분류, 링크 예측, 그래프 분류 등에 활용된다.
- 예시로 유튜브 카테고리 분류, 인스타그램 친구 추천, 쇼핑몰 아이템 추천, 분자 구조 기반 신약 반응성 예측 등이 있다.

---

### 2. 그래프 신경망의 구조와 심화 개념

- GNN에서 가장 중요한 구조는 이웃 노드의 정보를 어떻게 모을 것인지에 대한 Aggregation 전략이다.
- 스펙트럼 합성곱은 스펙트럼 그래프 이론에 기반한 수학적 합성곱 방식이다.
- 공간적 합성곱은 실제 연결된 이웃 노드와의 관계를 기반으로 정보를 집계하는 방식이다.
- GAT는 연결된 이웃 노드마다 어텐션 점수를 계산하여 더 중요한 노드의 정보를 더 크게 반영한다.
- 기존 GCN은 보통 2~3개 레이어 정도로 얕게 구성되는 경우가 많다.
- GCN이 더 깊어질 경우 과적합, 기울기 소실, 기울기 폭주 문제가 발생할 수 있다.
- GGNN은 GRU를 활용해 노드 표현을 갱신하고, 모든 레이어에서 가중치를 공유하여 더 깊은 구조를 만들 수 있다.
- 그래프 크기가 커지면 전체 인접행렬 계산 비용이 매우 커진다.
- 예를 들어 노드가 N개일 경우 N^2 수준의 연산이 필요할 수 있으며, 대규모 그래프에서는 샘플링 전략이 필요하다.

---

### 3. LangGraph

- LangGraph는 단순한 체인 구조의 한계를 보완하기 위해 그래프 형태로 AI 작업 흐름을 구성하는 방식이다.
- 체인은 한 방향으로만 진행되기 때문에 중간 결과가 부족해도 다시 돌아가기 어렵다.
- 반면 그래프는 조건에 따라 분기하거나, 결과가 부족하면 이전 단계로 되돌아가 재시도할 수 있다.
- LangGraph의 핵심 개념은 상태, 노드, 엣지이다.
- 상태는 작업 흐름에서 들고 다니는 가방과 같다.
- `TypedDict`로 상태를 정의하면 어떤 데이터가 오가는지 명확하게 관리할 수 있다.
- 노드는 하나의 함수이며, 특정 작업을 수행한다.
- 엣지는 노드와 노드를 연결하는 길이다.
- 조건부 엣지는 상황에 따라 다른 길로 이동하게 하는 분기 구조이다.
- 노드는 전체 상태를 반환할 필요 없이 바뀐 값만 반환하면 되고, LangGraph가 이를 기존 상태와 병합한다.
- 루프를 사용할 때는 `tries` 같은 카운터를 두어 무한 반복을 방지해야 한다.
- LangGraph는 검색, 검토, 재검색, 답변 생성, 환각 체크처럼 여러 단계를 조건에 따라 조합할 때 유용하다.

---

### 4. AI 휴먼 흐름에서의 활용

- AI 휴먼 서비스 흐름은 질문 -> 페르소나 -> RAG 검색 -> 답변 -> 환각 체크 -> TTS 음성 생성 구조로 볼 수 있다.
- 답변 근거가 부족하거나 환각 가능성이 있으면 다시 RAG 검색 단계로 돌아가 재검색할 수 있다.
- 이를 통해 AI가 바로 지어내는 것이 아니라, 근거를 확인하고 검증한 뒤 답변하는 구조를 만들 수 있다.
- LangGraph는 이런 분기, 재시도, 검증 흐름을 코드로 설계하는 데 적합하다.

## 핵심 개념 정리

| 개념 | 정리 |
|---|---|
| 그래프 | 노드와 엣지로 개체와 관계를 표현하는 자료구조 |
| 노드 | 그래프 안의 개체 |
| 엣지 | 노드 사이의 관계 |
| 인접행렬 | 노드 간 연결 여부를 행렬로 표현하는 방식 |
| 차수행렬 | 각 노드가 가진 연결 수를 대각행렬로 표현하는 방식 |
| 그래프 임베딩 | 그래프 구조를 벡터로 표현하는 방법 |
| GNN | 그래프 구조와 노드 특징을 함께 학습하는 딥러닝 모델 |
| Aggregation | 이웃 노드 정보를 모으는 과정 |
| Readout | 노드 표현을 모아 그래프 전체 표현을 만드는 과정 |
| GCN | 그래프 합성곱을 활용해 이웃 정보를 집계하는 모델 |
| GAT | 이웃 노드별 중요도를 어텐션으로 반영하는 모델 |
| GGNN | GRU를 활용해 노드 표현을 반복적으로 갱신하는 모델 |
| LangGraph | LLM 작업 흐름을 상태, 노드, 엣지 기반 그래프로 설계하는 프레임워크 |
| 조건부 엣지 | 상태에 따라 다음 노드를 다르게 선택하는 분기 구조 |

## 오늘의 회고

### 배운 점

- 그래프 데이터는 단순한 표나 이미지 데이터와 다르게 노드 간 관계 자체가 중요한 데이터라는 점을 배웠다.
- GNN은 노드 하나만 보는 것이 아니라 주변 이웃 노드의 정보를 함께 모아 표현을 학습한다는 점이 핵심이었다.
- 그래프 신경망에서 Aggregation, Readout, Neural Network가 각각 어떤 역할을 하는지 이해했다.
- LangGraph는 단순히 LLM을 호출하는 도구가 아니라, 조건 분기와 재시도 루프를 포함한 AI 작업 흐름을 설계하는 도구라는 점을 배웠다.
- AI 서비스에서 "검색 -> 검토 -> 부족하면 재검색 -> 답변" 같은 사람의 사고 흐름을 그래프 구조로 구현할 수 있다는 점이 인상적이었다.

### 어려운 점 / 개선할 점

- 스펙트럼 합성곱과 공간적 합성곱의 차이가 아직 직관적으로 완전히 와닿지는 않았다.
- 인접행렬, 차수행렬, 그래프 임베딩이 실제 코드에서 어떻게 연결되는지 더 연습이 필요하다.
- GCN, GAT, GGNN의 차이를 개념적으로는 이해했지만, 각각이 어떤 상황에서 더 적합한지는 추가 정리가 필요하다.
- LangGraph에서는 상태를 어떻게 설계하고, 어떤 값을 누적하거나 덮어쓸지 정하는 부분이 중요해 보인다.
- 루프를 만들 때 종료 조건을 빼먹으면 무한 반복이 발생할 수 있으므로 주의해야 한다.

## 액션 플랜

- GNN의 핵심 구조를 노드, 엣지, Aggregation, Readout 중심으로 그림으로 다시 정리한다.
- GCN, GAT, GGNN의 차이를 표로 비교한다.
- 인접행렬과 차수행렬을 간단한 예제 그래프로 직접 만들어본다.
- LangGraph의 상태, 노드, 엣지, 조건부 엣지 개념을 간단한 코드 흐름으로 복습한다.
- "검색 -> 검토 -> 재검색 -> 답변" 구조의 미니 LangGraph 예제를 만들어본다.
- AI 휴먼 프로젝트에 적용한다면 어떤 노드가 필요할지 흐름도를 그려본다.

## 함께 나누고 싶은 점

- GNN은 단순히 데이터를 벡터로 바꾸는 것이 아니라, 데이터 사이의 관계를 학습한다는 점에서 추천 시스템이나 지식 그래프와 연결성이 크다고 느꼈다.
- LangGraph는 AI가 한 번 답하고 끝나는 구조가 아니라, 스스로 검토하고 부족하면 다시 찾는 흐름을 만들 수 있다는 점에서 실서비스 설계에 유용해 보였다.
- 특히 RAG 기반 서비스에서 환각을 줄이기 위해 LangGraph의 재검색 루프와 검증 노드를 활용할 수 있을 것 같다.
