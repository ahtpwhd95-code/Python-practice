# 2026-05-15 SQL 기초 복습 - 조회, 집계, JOIN, 서브쿼리

## 오늘 학습한 내용

### 1. 기본 조회와 조건 검색
- `SELECT`, `FROM`, `WHERE`를 이용해 원하는 데이터를 조회했다.
- 문자열 조건과 숫자 조건을 구분해서 작성하는 연습을 했다.
  - 컬럼명은 따옴표 없이 작성
  - 문자열 값은 작은따옴표로 작성
- 여러 조건을 처리할 때 `AND`, `OR`를 사용했다.
- 여러 값 중 하나를 비교할 때는 `IN`을 사용했다.
- 특정 문자열 패턴을 찾을 때는 `LIKE`와 `%` 와일드카드를 사용했다.

```sql
SELECT *
FROM shareholder
WHERE name IN ('Alexis', 'Craig', 'Fred');
```

```sql
SELECT *
FROM book
WHERE title LIKE '% and %';
```

---

### 2. 집계 함수
- `COUNT`, `SUM`, `AVG`, `MAX`, `MIN`을 사용해 데이터를 계산했다.
- 전체 데이터에 대한 합계, 평균, 최댓값, 최솟값을 구할 수 있었다.
- 조건을 먼저 적용한 뒤, 조건에 맞는 데이터만 대상으로 집계할 수 있다는 점을 확인했다.

```sql
SELECT MAX(price), MIN(price)
FROM books
WHERE publication_year BETWEEN 2001 AND 2003;
```

---

### 3. GROUP BY와 HAVING
- `GROUP BY`는 같은 값을 기준으로 데이터를 묶을 때 사용한다.
- 카테고리별, 유저별, 부서별처럼 그룹 단위의 통계를 구할 수 있다.
- `WHERE`는 그룹화 전 데이터를 먼저 거르는 조건이고,
  `HAVING`은 그룹화 후 결과에 조건을 거는 방식이다.

```sql
SELECT user_id, COUNT(id)
FROM rental
GROUP BY user_id;
```

```sql
SELECT user_id, COUNT(id)
FROM rental
GROUP BY user_id
HAVING COUNT(id) >= 2;
```

#### 이해한 방식
- `WHERE` : 전처리
- `GROUP BY` : 같은 값끼리 묶기
- `HAVING` : 묶은 결과에 대한 후처리

---

### 4. JOIN
- `JOIN`은 두 개 이상의 테이블을 공통 컬럼 기준으로 연결할 때 사용한다.
- `ON`은 어떤 컬럼을 기준으로 연결할지 정하는 조건이다.
- `INNER JOIN`은 두 테이블에 모두 존재하는 데이터만 조회하는 교집합 개념으로 이해했다.
- `LEFT JOIN`은 왼쪽 테이블을 기준으로 모두 살리고, 오른쪽 테이블의 값이 있으면 붙이는 방식이다.

```sql
SELECT o.order_id, c.name, o.order_date, o.status
FROM orders o
INNER JOIN customer c
ON o.customer_id = c.customer_id;
```

```sql
SELECT c.customer_id, c.name, o.order_id, o.status
FROM customer c
LEFT JOIN orders o
ON c.customer_id = o.customer_id;
```

#### JOIN에서 배운 점
- `ON` 조건이 없으면 테이블이 기준 없이 연결되어 불필요한 조합이 많이 생길 수 있다.
- 기준 테이블을 명확히 잡는 것이 중요하다.
- `RIGHT JOIN`은 테이블 순서를 바꾸면 `LEFT JOIN`으로 표현할 수 있어, 우선 `LEFT JOIN` 중심으로 이해했다.

---

### 5. 여러 테이블 JOIN
- `orders`, `customer`, `order_item`, `product`처럼 여러 테이블을 연결해 주문 정보를 조회했다.
- 주문번호, 고객명, 상품명, 수량, 가격을 한 번에 출력할 수 있었다.
- 실제 서비스 데이터는 여러 테이블에 나뉘어 저장되기 때문에 JOIN이 중요하다는 것을 느꼈다.

```sql
SELECT 
    o.order_id,
    c.name AS customer_name,
    p.product_name,
    oi.quantity,
    p.price
FROM orders o
JOIN customer c
ON o.customer_id = c.customer_id
JOIN order_item oi
ON o.order_id = oi.order_id
JOIN product p
ON oi.product_id = p.product_id;
```

## 서브쿼리

### 6. 단일 행 서브쿼리
- 서브쿼리 결과가 하나의 값일 때 `=`, `>`, `<`, `>=` 같은 단일 행 비교 연산자를 사용할 수 있다.
- 기준값을 먼저 서브쿼리로 구한 뒤, 메인 쿼리에서 그 값과 비교하는 방식이다.

```sql
SELECT *
FROM product
WHERE price > (
    SELECT AVG(price)
    FROM product
);
```

#### 이해한 방식
- 서브쿼리 : 기준값 하나 구하기
- 메인쿼리 : 그 기준값과 비교하기

---

### 7. 다중 행 서브쿼리 - IN
- 서브쿼리 결과가 여러 행일 때 `IN`을 사용할 수 있다.
- 특정 목록 안에 포함되는 값인지 비교할 때 사용한다.

```sql
SELECT *
FROM emp
WHERE sal IN (
    SELECT MAX(sal)
    FROM emp
    GROUP BY deptno
);
```

---

### 8. 스칼라 서브쿼리
- `SELECT` 절 안에서 사용하는 서브쿼리를 스칼라 서브쿼리라고 한다.
- 각 행마다 하나의 값을 계산해서 컬럼처럼 붙일 수 있다.
- 바깥 쿼리의 값과 안쪽 쿼리를 연결하는 조건이 필요했다.

```sql
SELECT DISTINCT 
    s1.emp_no,
    (
        SELECT AVG(s2.salary)
        FROM salaries s2
        WHERE s2.emp_no = s1.emp_no
    ) AS avg_salary
FROM salaries s1;
```

---

### 9. EXISTS / NOT EXISTS
- `EXISTS`는 서브쿼리 결과의 값 자체를 가져오는 것이 아니라,
  조건에 맞는 행이 존재하는지 확인한다.
- `NOT EXISTS`는 조건에 맞는 행이 존재하지 않는 경우를 찾는다.
- `EXISTS` 안에서는 실제 출력값이 중요하지 않기 때문에 `SELECT 1`을 자주 사용한다.

```sql
SELECT c.customer_id, c.name
FROM customer c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
```

```sql
SELECT c.customer_id, c.name
FROM customer c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
```

#### 중요했던 점
- `EXISTS`를 사용할 때는 바깥 테이블과 안쪽 테이블을 연결하는 조건이 필요하다.
- 연결 조건이 없으면 전체 테이블에 대해 존재 여부만 판단하게 되어 잘못된 결과가 나올 수 있다.

---

### 10. ANY / ALL
- `ANY`는 서브쿼리 결과 중 하나라도 조건을 만족하면 참이다.
- `ALL`은 서브쿼리 결과 전체에 대해 조건을 만족해야 참이다.

```sql
SELECT *
FROM food
WHERE price > ANY (
    SELECT price
    FROM food
    WHERE food_type = 'Main'
)
ORDER BY food_id;
```

```sql
SELECT *
FROM employee e
WHERE e.salary >= ALL (
    SELECT e2.salary
    FROM employee e2
    WHERE e2.position = '사원'
);
```

#### 이해한 방식
- `> ANY` : 목록 중 하나보다만 크면 됨
- `> ALL` : 목록 전체보다 커야 함

---

### 11. 다중 컬럼 서브쿼리
- 두 개 이상의 컬럼을 함께 비교할 때는 왼쪽 컬럼들도 괄호로 묶어야 한다.
- `(컬럼1, 컬럼2) IN (...)` 형태로 사용한다.
- 책 이름이 같아도 작가가 다를 수 있는 경우처럼, 여러 컬럼 조합으로 비교해야 할 때 사용한다.

```sql
SELECT *
FROM book
WHERE (book_name, book_writer) IN (
    SELECT book_name, book_writer
    FROM book_stock
    WHERE stock >= 1
)
ORDER BY book_id;
```

## 핵심 정리
- `WHERE`는 그룹화 전 데이터를 거르는 전처리 조건이다.
- `HAVING`은 그룹화 후 결과에 조건을 거는 후처리 조건이다.
- `INNER JOIN`은 두 테이블의 교집합이다.
- `LEFT JOIN`은 기준 테이블을 모두 살리고, 연결되는 데이터가 있으면 붙인다.
- `ON` 조건이 없으면 JOIN 결과가 불필요하게 많이 늘어날 수 있다.
- `EXISTS`는 값을 가져오는 것이 아니라 조건에 맞는 행이 존재하는지 확인한다.
- `ANY`는 하나라도 만족하면 되고, `ALL`은 모두 만족해야 한다.
- 다중 컬럼 비교는 `(컬럼1, 컬럼2)`처럼 괄호로 묶어야 한다.
- 총액 계산에서는 단순 가격 합산이 아니라 `수량 * 가격`을 기준으로 계산해야 한다.

## 느낀 점
- SQL은 단순히 문법을 외우는 것보다 데이터가 어떤 순서로 필터링되고 연결되는지 이해하는 것이 중요하다고 느꼈다.
- 처음에는 JOIN과 서브쿼리가 복잡하게 느껴졌지만, 직접 쿼리를 작성하고 에러를 확인하면서 개념이 더 잘 잡혔다.
- 특히 `WHERE = 전처리`, `HAVING = 후처리`, `INNER JOIN = 교집합`, `LEFT JOIN = 기준 테이블 유지`처럼 내 방식으로 비유하니 이해하기 쉬웠다.
- 틀린 문제들도 대부분 방향은 맞았고, 연결 조건이나 비교 컬럼, 계산식 같은 세부 문법에서 한끝 차이로 실수했다.
- 오늘은 SQL을 데이터를 조립하고 분석하는 도구로 조금 더 이해하게 된 날이었다.
