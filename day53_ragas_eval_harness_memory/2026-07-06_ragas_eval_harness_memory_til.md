# RAGAS 평가 하네스와 지속 메모리 기반 AI 휴먼 품질 관리

## 📝 오늘 배운 내용 요약

오늘은 AI 휴먼/RAG 시스템을 단순히 “잘 되는 것 같다”가 아니라 **숫자로 평가하고, 자동으로 검증하며, 사용자를 기억하는 구조**까지 배웠다.

오늘 배운 내용은 크게 세 가지다.

1. **RAGAS**

   * RAG 품질을 자동으로 채점하는 평가 도구
   * 검색 품질과 생성 품질을 0~1 점수로 확인

2. **Evaluation Harness**

   * 한 번 평가에서 끝나는 것이 아니라, 수정할 때마다 자동으로 재평가하는 시스템
   * 점수가 떨어지면 회귀로 판단하고 차단

3. **지속 메모리 & 개인화**

   * 세션이 바뀌어도 사용자를 기억하는 AI 휴먼 구조
   * 단기 기억, 장기 기억, 프로필 메모리를 함께 사용

> 오늘의 핵심 문장:
> **AI 품질은 느낌이 아니라 평가로 증명하고, AI 휴먼은 기억으로 관계를 만든다.**

## 1. RAGAS

RAGAS는 RAG 시스템의 품질을 자동으로 평가하는 도구다.
질문, 답변, 검색된 문서, 정답을 넣으면 RAG의 성능을 여러 지표로 채점한다.

RAG는 크게 두 단계로 나뉜다.

* 검색 단계: 어떤 문서를 가져왔는가
* 생성 단계: 가져온 문서를 근거로 제대로 답했는가

그래서 RAGAS 지표도 검색 지표와 생성 지표로 나뉜다.

### RAGAS 핵심 4지표

| 지표                | 단계 | 의미                 |
| ----------------- | -- | ------------------ |
| Context Precision | 검색 | 쓸모 있는 문서가 상위에 있는가  |
| Context Recall    | 검색 | 필요한 문서를 빠짐없이 가져왔는가 |
| Faithfulness      | 생성 | 답변이 문서에 근거하는가      |
| Answer Relevancy  | 생성 | 답변이 질문에 맞는가        |

### Context Precision

검색 결과의 정렬 품질을 본다.
관련 없는 문서가 위에 있고 정답 문서가 아래에 있으면 점수가 낮아진다.

낮을 때 처방:

* 리랭킹 추가
* 청크 품질 개선
* 검색 k 조정
* 노이즈 문서 제거

### Context Recall

정답에 필요한 근거를 검색이 빠짐없이 가져왔는지 본다.
이 지표는 정답 reference가 있어야 제대로 측정할 수 있다.

낮을 때 처방:

* chunk_size 조정
* overlap 조정
* 검색 k 늘리기
* 하이브리드 검색 적용

### Faithfulness

답변이 검색된 문서에 근거하는지 본다.
문서에 없는 내용을 지어내면 점수가 낮아진다.

AI 휴먼에서는 특히 중요한 지표다.
화면 속 사람이 확신 있게 틀린 말을 하면 신뢰가 크게 무너지기 때문이다.

낮을 때 처방:

* “문서에 없으면 모른다고 답해” 프롬프트 추가
* 인용 강제
* temperature 낮추기
* 더 좋은 생성 모델 사용

### Answer Relevancy

답변이 질문에 제대로 대응하는지 본다.
답이 장황하거나 동문서답이면 점수가 낮아진다.

낮을 때 처방:

* 프롬프트 명확화
* 질문 재작성
* 답변 형식 지정
* 불필요한 배경 설명 줄이기

## 2. RAGAS 평가 데이터셋

RAGAS 평가용 데이터는 보통 한 문항이 네 칸으로 구성된다.

| 항목                       | 설명            |
| ------------------------ | ------------- |
| question                 | 사용자 질문        |
| answer                   | 내 RAG가 생성한 답변 |
| contexts                 | 검색해온 문서 조각    |
| ground_truth / reference | 모범답안          |

실무에서는 내 RAG를 실제로 돌려서 answer와 contexts를 자동으로 채운다.
학습용으로는 일부러 환각 문항이나 동문서답 문항을 섞어 RAGAS가 잘 잡는지 확인할 수 있다.

주의할 점:

* 문항 수가 너무 적으면 점수가 우연에 흔들린다.
* 최소 20개 이상, 가능하면 50개 이상이 좋다.
* 평균 점수만 보지 말고 문항별 점수를 확인해야 한다.
* 한국어 평가에는 한국어에 강한 LLM과 임베딩을 써야 한다.

---

## 3. RAGAS에서 자주 터지는 실수

| 실수                     | 문제                             |
| ---------------------- | ------------------------------ |
| 문항이 너무 적음              | 점수가 우연에 크게 흔들림                 |
| 영어 채점 모델 사용            | 한국어 평가가 불안정해질 수 있음             |
| reference 없이 Recall 기대 | Context Recall은 정답이 없으면 의미가 약함 |
| 평균 점수만 봄               | 어떤 질문이 약한지 알 수 없음              |
| 비용과 시간 무시              | 지표마다 LLM 호출이 많아져 느릴 수 있음       |

> RAGAS는 “잘 되는 것 같아요”를 “0.62에서 0.85로 개선됐습니다”로 바꿔주는 도구다.

## 4. 평가 하네스

RAGAS가 한 번 채점하는 도구라면, 평가 하네스는 그 채점을 **자동화된 시스템**으로 만든 것이다.

RAG를 수정할 때마다 사람이 손으로 평가하면 오래 못 간다.
평가 하네스는 고정된 시험지로 매번 자동 평가하고, 이전 점수와 비교해 성능이 떨어졌는지 확인한다.

### 평가 하네스 6대 구성요소

| 구성요소   | 역할                   |
| ------ | -------------------- |
| 골든셋    | 고정된 시험지              |
| 러너     | 내 RAG를 자동 실행         |
| 채점기    | RAGAS와 LLM Judge로 채점 |
| 점수 기록  | 실험별 점수 저장            |
| 회귀 게이트 | 점수 하락 시 차단           |
| 리포트    | 표와 그래프로 결과 확인        |

### 러너

러너는 골든셋의 질문을 하나씩 내 RAG에 넣고, 답변과 검색 문서를 자동으로 수집한다.

흐름:

1. 골든셋에서 질문을 꺼낸다.
2. retriever로 contexts를 가져온다.
3. RAG chain으로 answer를 만든다.
4. 평가 레코드를 생성한다.
5. RAGAS로 채점한다.

이 구조가 있으면 RAG를 고친 뒤 버튼 하나로 전체 평가를 다시 돌릴 수 있다.

---

## 5. RAGAS + LLM-as-Judge

평가 하네스에서는 두 종류의 채점기를 함께 사용할 수 있다.

### RAGAS

RAGAS는 표준 지표를 자동으로 계산한다.

* Context Precision
* Context Recall
* Faithfulness
* Answer Relevancy

### LLM-as-Judge

LLM-as-Judge는 서비스에 맞춘 주관적 기준을 평가한다.

예시:

* 페르소나 말투를 지켰는가
* 존댓말을 유지했는가
* 상담원답게 답했는가
* 위험한 상황에서 안전하게 응답했는가
* 브랜드 톤과 맞는가

RAGAS가 기본기를 본다면, LLM-as-Judge는 서비스만의 품질 기준을 본다.

주의할 점:

* LLM 채점관도 편향이 있다.
* 긴 답변을 더 좋게 볼 수 있다.
* 먼저 보여준 답을 선호할 수 있다.
* 자기 스타일의 답변을 더 좋게 볼 수 있다.
* temperature를 낮추고, 루브릭을 명확하게 줘야 한다.

---

## 6. 회귀 게이트

회귀 게이트는 기준 점수보다 낮아지면 실패 처리하는 장치다.

예를 들어 baseline 평균이 0.86인데 새 실험 점수가 0.83으로 떨어졌다면 회귀로 볼 수 있다.
특히 Faithfulness처럼 중요한 지표는 더 엄격하게 관리해야 한다.

예시 규칙:

* 평균 점수가 baseline보다 크게 낮아지면 실패
* Faithfulness는 절대 하락 금지
* 약간의 흔들림은 tolerance로 허용
* 실패하면 배포나 머지를 차단

> 코드에 테스트가 있듯이, RAG에는 평가 하네스가 있어야 한다.

## 7. 관측: Langfuse / Phoenix

평가 하네스는 점수가 떨어졌다는 사실을 알려준다.
하지만 왜 떨어졌는지는 별도로 관측해야 한다.

Langfuse나 Phoenix 같은 도구를 사용하면 한 요청의 전체 흐름을 trace로 볼 수 있다.

관측할 수 있는 것:

* 입력 토큰 수
* 출력 토큰 수
* 단계별 지연 시간
* 검색 결과
* 프롬프트
* LLM 응답
* 툴 호출
* 비용

평가가 점수라면, 관측은 그 점수가 나온 과정의 CCTV다.

활용 예시:

* 점수 하락 문항의 trace를 확인한다.
* 검색이 잘못됐는지 본다.
* 프롬프트가 너무 길어진 부분을 찾는다.
* 특정 툴 호출이 느린지 확인한다.
* 비용이 급증한 요청을 추적한다.

## 8. 지속 메모리와 개인화

AI 휴먼이 매번 사용자를 처음 보는 것처럼 행동하면 단순한 도구처럼 느껴진다.
반대로 사용자의 이름, 취향, 이전 대화를 기억하면 관계가 생긴다.

지속 메모리는 세션이 바뀌어도 사용자를 기억하는 구조다.

### 기억의 종류

| 종류     | 설명                      |
| ------ | ----------------------- |
| 단기 기억  | 현재 대화 히스토리              |
| 장기 기억  | 사용자에 대한 누적 사실           |
| 프로필 기억 | 이름, 취향, 반려동물 등 구조화된 값   |
| 일화 기억  | 언제 무슨 일이 있었는지에 대한 사건 기록 |
| 의미 기억  | 여러 사건에서 추출된 일반적 사실      |

---

## 9. 단기 기억

단기 기억은 지금 이 대화의 흐름이다.
LLM은 기본적으로 stateless이기 때문에, 이전 메시지를 직접 같이 넣어줘야 기억하는 것처럼 동작한다.

문제는 대화가 길어질수록 토큰이 폭증한다는 점이다.

해결 방법:

* 최근 N개 메시지만 유지하는 윈도우 방식
* 오래된 대화를 요약하는 방식
* system 메시지 아래에 이전 대화 요약을 넣는 방식

컴패니언 AI에서는 단순 윈도우보다 요약 방식이 더 적합하다.
오래된 사실을 버리지 않고 압축해서 유지할 수 있기 때문이다.

---

## 10. 장기 기억

장기 기억은 사용자에 대한 사실을 저장하고, 다음 세션에서도 다시 불러오는 구조다.

흐름:

1. 사용자 발화에서 기억할 만한 사실을 추출한다.
2. 사실 문장을 임베딩한다.
3. FAISS 같은 벡터스토어에 저장한다.
4. 다음 질문이 들어오면 관련 기억 top-k를 검색한다.
5. 검색된 기억을 system prompt에 자연스럽게 주입한다.

예시:

사용자 발화:

> 나 매운 음식 좋아해.

저장되는 기억:

> 사용자는 매운 음식을 좋아한다.

나중에 질문:

> 저녁 메뉴 추천해줘.

회수된 기억:

> 사용자는 매운 음식을 좋아한다.

답변:

> 매운 음식 좋아하시니까 마라탕이나 매운 닭갈비 괜찮을 것 같아요.

## 11. 자동 기억 추출

사용자가 매번 “이거 기억해”라고 말하지 않아도, LLM이 장기적으로 가치 있는 사실을 뽑을 수 있다.

기억할 것:

* 이름
* 취향
* 직업
* 반려동물
* 이사, 목표, 장기 계획
* 자주 반복되는 관심사

버릴 것:

* 인사
* 단발성 질문
* 일시적 감정
* 의미 없는 잡담
* 민감한 개인정보

중요한 점은 기억할 가치가 없으면 빈 배열을 반환하게 만드는 것이다.
파싱 실패 시에는 안전하게 무시하는 것이 좋다.

## 12. 프로필 딕셔너리

정확한 값은 벡터 메모리보다 딕셔너리로 관리하는 것이 좋다.

예시:

```json
{
  "이름": "수찬",
  "좋아하는 음식": "매운 음식",
  "반려동물": "고양이 두 마리"
}
```

프로필 딕셔너리는 같은 key를 덮어써서 최신 정보로 갱신할 수 있다.
예를 들어 반려동물이 “강아지”에서 “고양이 두 마리”로 바뀌면 기존 값을 업데이트한다.

벡터 메모리는 자유로운 서술형 사실에 좋고, 프로필 딕셔너리는 정확한 키-값 정보에 좋다.

## 13. 메모리에서 자주 터지는 실수

| 실수              | 문제               |
| --------------- | ---------------- |
| 모든 기억을 프롬프트에 넣음 | 토큰 폭증, 답변 산만     |
| 기억 갱신 안 함       | 오래된 사실과 새 사실이 충돌 |
| 개인정보 저장         | 보안과 윤리 문제 발생     |
| top-k 과다        | 관련 없는 기억이 섞임     |
| 히스토리 무한 누적      | 컨텍스트 한도 초과       |

메모리는 무조건 많이 저장하는 것이 좋은 게 아니다.
중요한 기억을 저장하고, 관련 있는 기억만 회수하고, 오래된 기억은 요약하거나 잊는 설계가 필요하다.

---

## 14. 하이브리드 기억

오래 쓰는 AI 휴먼은 한 가지 기억 방식만으로는 부족하다.

좋은 구조:

* 벡터 기억: 의미가 비슷한 기억 검색
* 그래프 기억: 사용자, 반려동물, 취향, 사건의 관계 저장
* 요약 기억: 오래된 대화와 일화를 압축
* 프로필 기억: 이름, 취향, 나이 같은 정확한 값 저장

> 단기 기억은 흐름, 일화 기억은 사건, 의미 기억은 결론이다.
> 이 셋을 분리하면 AI 휴먼이 더 사람답게 기억한다.

## 15. 통합 관점

오늘 배운 세 가지는 AI 휴먼의 품질 관리와 개인화를 연결한다.

1. RAGAS로 RAG 품질을 숫자로 평가한다.
2. 평가 하네스로 수정할 때마다 자동 재평가한다.
3. 회귀 게이트로 품질 하락을 막는다.
4. Langfuse/Phoenix로 왜 점수가 떨어졌는지 추적한다.
5. 지속 메모리로 사용자를 기억한다.
6. 관련 기억만 회수해 개인화된 답변을 만든다.
7. 민감정보는 저장하지 않고, 저장·삭제·갱신 정책을 둔다.

> 신뢰할 수 있는 AI 휴먼은 두 가지를 해야 한다.
> **답변 품질은 평가로 증명하고, 사용자 경험은 기억으로 이어가야 한다.**

---

## 💭 오늘의 회고

### 1. 배운 점

* RAG 품질은 느낌으로 판단하면 안 되고, RAGAS 같은 도구로 수치화해야 한다.
* RAGAS의 핵심 지표는 검색 2개, 생성 2개로 나눠서 볼 수 있다.
* Faithfulness는 환각을 잡는 지표라 AI 휴먼에서 특히 중요하다.
* 평가 하네스는 RAGAS 평가를 반복 가능한 자동 시스템으로 만든다.
* 회귀 게이트를 사용하면 점수가 떨어진 변경을 배포 전에 차단할 수 있다.
* Langfuse와 Phoenix 같은 관측 도구는 점수 하락의 원인을 추적하는 데 필요하다.
* 지속 메모리는 AI 휴먼을 단순 챗봇이 아니라 사용자를 기억하는 컴패니언으로 만든다.
* 단기 기억, 장기 기억, 프로필 기억은 역할이 다르므로 분리해서 관리해야 한다.

### 2. 어려운 점 / 개선할 점

* RAGAS 점수는 평균만 보면 안 되고, 문항별로 어떤 질문이 약한지 직접 확인해야 한다.
* 한국어 평가에는 한국어에 강한 채점 LLM과 임베딩을 직접 주입해야 한다.
* 골든셋이 적으면 점수가 우연에 흔들릴 수 있으므로 충분한 문항이 필요하다.
* LLM-as-Judge는 편향이 있으므로 루브릭과 검증이 중요하다.
* 메모리는 많이 저장하는 것보다 무엇을 저장하지 않을지 정하는 것이 더 중요하다.
* 개인정보와 민감정보는 저장 전에 반드시 걸러야 한다.
* 오래된 기억과 새 기억이 충돌할 때 갱신 정책이 필요하다.

### 3. 액션 플랜

* RAGAS 4지표를 기준으로 현재 RAG 결과를 평가해본다.
* 최소 20개 이상의 골든셋을 만들어 질문, 정답, 검색 문서를 정리한다.
* 개선 전/후 RAGAS 점수를 비교해본다.
* 문항별 점수를 확인해 낮은 질문 TOP 3를 분석한다.
* 평가 하네스 구조를 만들어 자동으로 RAG를 실행하고 채점하게 한다.
* baseline 점수를 저장하고 회귀 게이트를 적용한다.
* Langfuse 또는 Phoenix로 RAG 요청 trace를 기록해본다.
* 사용자 발화에서 기억할 사실을 추출하는 JSON 추출 프롬프트를 만든다.
* 벡터 메모리와 프로필 딕셔너리를 함께 설계한다.
* 민감정보 저장 금지, 기억 삭제, 기억 갱신 정책을 정리한다.

### 4. 함께 나누고 싶은 점

* AI 서비스를 만들 때 “잘 되는 것 같다”는 말은 설득력이 약하다.
* RAGAS와 평가 하네스를 쓰면 “무엇을 고쳤고, 점수가 얼마나 좋아졌는지”를 보여줄 수 있다.
* AI 휴먼은 말투와 얼굴만으로 사람처럼 느껴지는 것이 아니라, 나를 기억하고 이어서 대화할 때 관계처럼 느껴진다.
* 하지만 기억은 강력한 만큼 개인정보와 신뢰 문제가 크기 때문에 저장 기준과 삭제 기능이 필수다.
* 좋은 AI 휴먼은 평가로 품질을 지키고, 메모리로 개인화를 만든다.
