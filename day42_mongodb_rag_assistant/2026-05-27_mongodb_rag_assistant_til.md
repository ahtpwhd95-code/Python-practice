### 2. MongoDB 연동 및 샘플 데이터 저장

- 로컬 MongoDB 서버에 연결하는 방법을 실습했다.

```python
MongoClient("mongodb://localhost:27017/")
```

- `LocalAssistantDB` 데이터베이스를 사용했다.
- 다음 3개의 컬렉션을 생성하고 활용했다.
  - `trips`: 출장 기록
  - `expenses`: 지출 내역
  - `photos`: 사진 메타데이터
- 출장, 지출, 사진 관련 샘플 데이터를 MongoDB에 저장했다.
- 실행 결과 샘플 데이터 저장이 성공적으로 완료되었다.

```text
DB ✅ 샘플 데이터가 MongoDB에 성공적으로 저장되었습니다.
```

---

### 3. RAG + LLM 구조 이해

- 오늘 실습한 `app.py`는 사용자의 질문을 받아 Gemini가 질문 의도를 분석하고, MongoDB에서 관련 데이터를 검색한 뒤, 검색 결과를 Context로 넣어 최종 답변을 생성하는 구조였다.
- 단순히 LLM에게 질문하는 방식이 아니라, 내부 데이터베이스에서 관련 정보를 검색한 뒤 답변을 생성하는 텍스트 기반 RAG&LLM 구조를 실습했다.

```text
사용자 질문
-> Gemini가 질문 의도 분석
-> MongoDB에서 관련 데이터 검색
-> 검색 결과를 Context로 구성
-> Gemini가 최종 답변 생성
```


- API 기반 실습에서는 키 관리와 환경변수 설정이 중요하다는 점을 확인했다.

---

### 5. STT -> RAG&LLM -> TTS 구조 개념

- 선생님이 설명한 전체 구조는 다음과 같았다.

```text
STT -> RAG&LLM -> TTS
```

- STT는 음성을 텍스트로 변환하는 단계이다.
- RAG&LLM은 검색 기반으로 AI 답변을 생성하는 단계이다.
- TTS는 텍스트 답변을 음성으로 출력하는 단계이다.
- 오늘은 전체 음성 서비스 중 실제로는 RAG&LLM 중심의 데이터 검색 및 답변 생성 구조를 실습했다.

## 핵심 흐름 정리

| 단계 | 역할 |
|---|---|
| Pillow | 이미지 처리 기반 라이브러리 |
| MongoDB | 출장, 지출, 사진 메타데이터 저장소 |
| Gemini | 질문 의도 분석 및 최종 답변 생성 |
| Context 구성 | 검색된 DB 결과를 LLM 입력으로 정리 |
| RAG&LLM | 내부 데이터를 근거로 답변 생성 |
| STT | 음성을 텍스트로 변환 |
| TTS | 텍스트 답변을 음성으로 출력 |

## 오늘의 회고

### 배운 점

- MongoDB를 사용해 출장, 지출, 사진 메타데이터 같은 데이터를 컬렉션별로 저장하고 관리하는 방법을 배웠다.
- LLM이 단독으로 답변하는 것이 아니라, MongoDB에서 관련 데이터를 검색한 뒤 Context로 넣어 답변을 생성하는 RAG 구조를 이해했다.
- `STT -> RAG&LLM -> TTS` 흐름을 통해 음성 기반 AI 비서나 로컬 어시스턴트 서비스가 어떤 구조로 확장될 수 있는지 감을 잡았다.

### 어려운 점 / 개선할 점

- Gemini API 키 오류가 발생하여 최종 답변 생성까지 정상적으로 확인하지 못한 부분이 아쉬웠다.
- `.env` 파일, API 키 입력 위치, 환경변수 로딩 방식 등을 정확히 확인하는 습관이 필요하다고 느꼈다.
- RAG 구조에서 어떤 데이터를 검색하고, 어떤 내용을 Context로 넣어야 좋은 답변이 나오는지 더 연습이 필요하다.
