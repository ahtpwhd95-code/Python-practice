# 2026-07-08 TIL - 책임 AI와 Mini PERSO AI 통합 구조

## 오늘 배운 내용

오늘은 AI 휴먼을 만들 때 반드시 필요한 두 가지를 배웠다.

1. 책임 AI와 딥페이크 윤리
   - 얼굴 합성, 음성 클로닝, 립싱크 기술은 동의 없이 쓰이면 딥페이크가 될 수 있다.
   - 동의, 표기, 워터마크, 출처 기록, 탐지, 규제 이해가 함께 필요하다.

2. 통합 Mini PERSO AI

> 오늘의 핵심 문장: AI 휴먼은 만들 줄 아는 것만큼, 책임 있게 쓰고 안전하게 통합하는 것이 중요하다.

---

### 1. 책임 AI와 딥페이크 윤리

- 딥페이크는 딥러닝 기술을 이용해 얼굴, 목소리, 행동, 장면을 진짜처럼 합성하는 기술이다.
- 앞에서 배운 아바타 생성, 립싱크, 음성 클로닝 기술도 동의 없이 사용되면 딥페이크가 될 수 있다.
- 딥페이크의 핵심 문제는 기술 자체보다 동의 없는 사용과 진짜처럼 속이는 데 있다.

주요 위험:

| 위험 | 설명 |
|---|---|
| 사칭 | 유명인, 지인, 상사 얼굴이나 목소리로 위장 |
| 금융 사기 | 대표나 가족 목소리처럼 꾸며 송금 지시 |
| 명예훼손 | 허위 발언이나 합성 영상으로 평판 훼손 |
| 불법 합성물 | 동의 없는 성적·모욕적 합성물 제작 및 유포 |

특히 동의 없는 성적 합성물은 국내법상 강하게 처벌될 수 있다.

---

### 2. 동의와 권리

- 얼굴과 목소리는 개인의 정체성과 연결된 정보이다.
- AI 휴먼을 만들 때 가장 먼저 확인해야 할 것은 "이 얼굴과 목소리를 사용할 권리가 있는가?"이다.

| 개념 | 설명 |
|---|---|
| 초상권 | 자신의 얼굴이나 모습이 함부로 쓰이지 않을 권리 |
| 음성권 | 자신의 목소리가 무단 복제되거나 악용되지 않을 권리 |
| 정보주체 동의 | 목적, 범위, 기간을 알리고 받는 동의 |
| 철회권 | 사용자가 언제든 동의를 철회할 수 있는 권리 |

좋은 동의에 포함되어야 할 것:

- 어디에 사용할 것인지
- 어떤 방식으로 합성할 것인지
- 얼마 동안 사용할 것인지
- 결과물을 어디에 공개할 것인지
- 철회하면 어떻게 삭제할 것인지

> 공개된 사진이나 영상이라고 해서 마음대로 학습하거나 합성해도 되는 것은 아니다.

---

### 3. 워터마크와 출처 기록

- 생성 AI 콘텐츠는 진짜와 가짜를 구분하기 어려울 수 있다.
- 따라서 만든 콘텐츠에 표식을 남기고, 생성 이력을 기록하는 것이 중요하다.

보이는 워터마크:

- 사람이 직접 볼 수 있는 표시이다.
- "AI 생성 이미지", "AI 아바타", 로고, 배지, 영상 하단 고지 문구 등이 있다.
- 사용자가 즉시 알아볼 수 있지만, 잘라내거나 가리면 사라질 수 있다.

보이지 않는 워터마크:

- 이미지 픽셀이나 주파수 영역에 사람이 볼 수 없는 신호를 숨기는 방식이다.
- 눈에 보이지 않고 기계가 검출할 수 있지만, 강한 변형에는 손상될 수 있다.
- 완벽하게 지워지지 않는 워터마크는 없다는 점을 이해해야 한다.

C2PA 출처 기록:

- C2PA는 콘텐츠의 생성·편집 이력을 서명된 메타데이터로 남기는 방식이다.
- 어떤 도구로 만들었는지, 어떤 모델을 사용했는지, 언제 생성했는지, 어떤 편집이 있었는지, 제작자 서명 등을 기록할 수 있다.
- 워터마크가 픽셀 속 표식이라면, C2PA는 콘텐츠의 이력서에 가깝다.

### 4. 딥페이크 탐지와 규제

- 딥페이크 탐지는 생성물에 남는 미세한 흔적을 보고 진짜와 가짜를 구분하려는 기술이다.
- 탐지기는 눈 깜빡임, 얼굴 경계, 조명 불일치, 주파수 패턴, 워터마크 신호, 생성 모델 특유의 흔적 등을 본다.
- 하지만 탐지는 완벽하지 않다. 새로운 생성 모델이 나오면 기존 탐지기가 잘 못 잡을 수 있다.
- 그래서 사후 탐지보다 예방이 더 중요하다.

| 구분 | 방법 |
|---|---|
| 예방 | 동의, 표기, 워터마크, 출처 기록 |
| 사후 대응 | 탐지, 신고, 삭제, 법적 대응 |

국내외 규제 흐름도 공통적으로 AI 생성물 표기와 동의 없는 합성물 금지를 강조한다.

### 5. AI 휴먼 제작 전 체크리스트

AI 휴먼 콘텐츠를 만들기 전후로 아래 질문을 확인해야 한다.

1. 얼굴과 목소리 주인의 동의를 받았는가?
2. AI 생성 콘텐츠임을 명확히 표기했는가?
3. 워터마크나 검증 가능한 표식을 넣었는가?
4. 생성·편집 내력을 기록했는가?
5. 사칭, 기만, 피해 가능성이 없는가?
6. 동의 철회나 삭제 요청에 대응할 수 있는가?

하나라도 "아니오"라면 제작이나 공개를 멈추고 다시 점검해야 한다.

### 6. 통합 Mini PERSO AI

- Mini PERSO AI는 지금까지 따로 배운 기능들을 하나로 묶은 미니 AI 휴먼 구조이다.
- 새로운 개념이라기보다 페르소나, RAG, 장기기억, 대화 히스토리, TTS, 가드레일을 조립하는 구조이다.

| 블록 | 역할 |
|---|---|
| 페르소나 | 이름, 말투, 성격을 시스템 프롬프트로 고정 |
| RAG 지식검색 | 일반 지식을 FAISS에서 검색 |
| 장기기억 | 사용자 정보를 별도 FAISS에 저장하고 회수 |
| 대화 히스토리 | 최근 대화 흐름 유지 |
| TTS | 답변을 음성으로 출력 |
| 가드레일 | 민감정보, 위험 요청, 환각 방지 |

### 7. 한 턴의 전체 흐름

Mini PERSO AI의 `chat()` 한 번은 한 턴 전체를 처리한다.

흐름:

1. 사용자 입력을 받는다.
2. 입력이 기억할 정보인지 지식 질문인지 판단한다.
3. 기억할 정보라면 장기기억에 저장한다.
4. 지식 질문이라면 RAG 지식검색을 수행한다.
5. 사용자 관련 기억을 장기기억에서 회수한다.
6. 페르소나 시스템 프롬프트를 만든다.
7. 지식 컨텍스트와 기억 컨텍스트를 합쳐 LLM에 넣는다.
8. 답변을 생성한다.
9. 대화 이력을 업데이트한다.
10. 필요하면 TTS로 음성을 출력한다.

> 핵심 질문은 세 가지이다. 누가 말하는가? 무엇을 알고 있는가? 나를 기억하는가?

---

### 8. 기억과 지식은 분리해야 한다

Mini PERSO AI에서 중요한 원칙은 기억과 지식을 다른 저장소에 넣는 것이다.

| 구분 | 내용 | 저장소 |
|---|---|---|
| 지식 | RAG 문서, AI 개념, 도메인 정보 | knowledge_index |
| 기억 | 이름, 취향, 과거 대화, 사용자 정보 | LongTermMemory |
| 대화 이력 | 현재 세션의 최근 대화 | history |

기억과 지식을 같은 인덱스에 넣으면 검색 결과가 섞여서 답변이 이상해질 수 있다.

예시:

- "RAG가 뭐야?"라는 질문에 사용자 취향 기억이 검색될 수 있다.
- "내 이름 기억해?"라는 질문에 일반 지식 문서가 검색될 수 있다.

### 9. 페르소나 고정

AI 휴먼이 일관되게 느껴지려면 페르소나를 시스템 프롬프트로 고정해야 한다.

페르소나에 들어갈 요소:

- 이름
- 말투
- 성격
- 답변 길이
- 금지 행동
- 지식이 없을 때의 응답 방식
- 사용자 기억을 사용하는 방식

예시:

```text
너는 '하루'라는 AI 휴먼이다.
밝고 다정한 말투로 답한다.
어려운 개념은 쉬운 비유로 설명한다.
관련 지식에 근거해서 답하고, 없으면 모른다고 말한다.
사용자 기억은 자연스럽게 활용하되 과하게 드러내지 않는다.
```

페르소나가 약하거나 매 턴 빠지면 말투가 쉽게 무너진다.

### 10. 프롬프트 폭증 방지

통합 시스템에서 가장 자주 터지는 문제는 프롬프트가 너무 길어지는 것이다.

매 턴마다 아래 내용을 모두 넣으면 토큰이 폭발한다.

- 전체 대화 이력
- 모든 사용자 기억
- 모든 지식 문서
- 긴 페르소나 설명

추천 구조:

- 시스템 프롬프트: 페르소나 고정
- 지식 검색: top-3만 사용
- 기억 검색: top-3만 사용
- 대화 이력: 최근 6턴만 사용
- 오래된 대화: 요약 메모리로 압축

> 매 턴 프롬프트 길이를 일정하게 유지해야 속도와 비용을 예측할 수 있다.

### 11. 프로젝트 확장 방향

오늘 만든 Mini PERSO AI는 프로젝트3의 출발점이 될 수 있다.

| 미니 버전 | 프로젝트 확장 |
|---|---|
| 지식 문서 하드코딩 | 파일·DB에서 도메인 문서 로드 |
| 페르소나 1개 | 여러 페르소나 선택/전환 |
| 단순 FAISS 검색 | 하이브리드 검색 + 리랭킹 |
| 세션 한정 기억 | 디스크 저장으로 영속화 |
| 평가 없음 | RAGAS로 품질 평가 |
| 간단한 분기 | LLM 라우터 / LangGraph |
| 텍스트 답변 | TTS와 아바타 연결 |
| 기본 응답 | 가드레일과 출처 표시 추가 |

프로젝트3는 완전히 새로 만드는 것이라기보다, 오늘 만든 뼈대를 실제 데이터와 운영 수준으로 키우는 작업에 가깝다.

### 12. 통합할 때 자주 터지는 실수

| 실수 | 문제 |
|---|---|
| 프롬프트 폭증 | 이력·기억·지식을 전부 넣어 토큰 폭발 |
| 기억/지식 혼동 | 같은 인덱스에 섞어 검색 결과가 망가짐 |
| 페르소나 깨짐 | 시스템 프롬프트가 약하거나 누락됨 |
| 환각 | 지식에 없는 내용을 지어냄 |
| 빈 인덱스 에러 | 첫 대화에는 기억이 없는데 검색을 시도함 |
| 개인정보 관리 부족 | 사용자 기억을 무분별하게 저장함 |

해결 원칙:

- 페르소나는 항상 시스템 프롬프트 최상단에 둔다.
- 기억과 지식 저장소를 분리한다.
- 검색 결과는 top-k로 제한한다.
- 지식에 없으면 모른다고 답하게 한다.
- 빈 기억 저장소는 None 분기로 막는다.
- 민감정보는 저장하지 않는다.

### 13. 상속으로 기능 확장하기

- `MiniPersoAI` 클래스를 직접 계속 수정하면 구조가 지저분해질 수 있다.
- 기본 클래스는 유지하고, 필요한 기능은 자식 클래스로 확장할 수 있다.

예시 확장:

- 페르소나 교체
- 가드레일 추가
- 출처 표시 추가
- 민감정보 차단
- TTS 연결
- 라우터 추가

장점:

- 기존 흐름을 유지할 수 있다.
- `super().chat()`으로 기본 동작을 재사용할 수 있다.
- 기능을 겹겹이 추가하기 쉽다.
- 실험과 확장이 깔끔해진다.

### 14. 통합 관점

오늘 배운 책임 AI와 Mini PERSO AI는 서로 연결된다.

Mini PERSO AI가 얼굴, 목소리, 기억, RAG, TTS를 통합한다면, 책임 AI는 그 위에 안전장치를 다는 역할을 한다.

AI 휴먼을 실제 서비스로 만들려면 다음이 함께 필요하다.

1. 동의받은 얼굴과 목소리만 사용한다.
2. AI 생성 콘텐츠임을 표기한다.
3. 워터마크와 출처 기록을 남긴다.
4. 기억과 개인정보를 안전하게 관리한다.
5. RAG는 근거 기반으로 답하게 한다.
6. 페르소나는 일관되게 유지한다.
7. 위험 요청에는 가드레일을 적용한다.
8. 삭제와 철회 요청에 대응할 수 있어야 한다.

> 좋은 AI 휴먼은 그럴듯하게 보이는 AI가 아니라, 동의받고, 표기하고, 근거로 답하고, 사용자를 안전하게 기억하는 AI이다.

## 오늘의 회고

### 배운 점

- 얼굴 합성, 음성 클로닝, 립싱크 기술은 강력하지만 동의 없이 쓰이면 딥페이크가 될 수 있다.
- 딥페이크의 핵심 문제는 기술이 아니라 동의, 표기, 진위, 피해 가능성이다.
- AI 생성물에는 보이는 표기와 보이지 않는 워터마크를 함께 사용하는 것이 좋다.
- C2PA 같은 출처 기록은 콘텐츠의 생성·편집 이력을 남기는 방식이다.
- 탐지는 완벽하지 않기 때문에 사후 탐지보다 예방이 중요하다.
- Mini PERSO AI는 페르소나, 기억, RAG, TTS를 하나로 묶은 통합 구조이다.
- 기억과 지식은 반드시 다른 저장소에 분리해야 한다.
- 프로젝트3는 Mini PERSO AI 구조를 실제 데이터와 평가, 운영 수준으로 확장하는 방향으로 볼 수 있다.

### 어려운 점 / 개선할 점

- 동의와 표기 기준을 실제 프로젝트 문서에 어떻게 명확히 넣을지 고민이 필요하다.
- 워터마크가 어떤 변형까지 견디는지 직접 실험해봐야 한다.
- C2PA와 보이지 않는 워터마크의 차이를 더 익혀야 한다.
- Mini PERSO AI에서 기억, 지식, 히스토리가 섞이지 않도록 구조를 잘 나눠야 한다.
- 프롬프트가 길어지지 않게 top-k와 최근 대화 수를 제한하는 설계가 필요하다.
- 페르소나가 여러 턴 동안 깨지지 않는지 테스트해야 한다.
- 사용자 기억에는 개인정보가 들어갈 수 있으므로 저장 기준과 삭제 정책이 필요하다.

## 액션 플랜

- AI 휴먼 제작 전 체크리스트를 프로젝트 문서에 추가한다.
- 이미지 워터마크 삽입과 검출 실습을 해본다.
- 리사이즈, JPEG 압축 후에도 워터마크가 남는지 테스트한다.
- 생성 콘텐츠에 "AI 생성" 표기 문구를 붙이는 방식을 정한다.
- `MiniPersoAI` 클래스 구조를 정리한다.
- `knowledge_index`와 `LongTermMemory`를 분리해서 구현한다.
- 페르소나 시스템 프롬프트를 딕셔너리로 관리한다.
- `chat()` 한 번에 의도판단, 기억 저장, 지식 검색, 기억 회수, 답변 생성을 연결한다.
- 기억 top-3, 지식 top-3, 최근 6턴처럼 프롬프트 길이 제한 규칙을 둔다.
- RAGAS와 가드레일을 붙여 Mini PERSO AI를 프로젝트 수준으로 확장한다.

## 함께 나누고 싶은 점

- AI 휴먼은 사람처럼 보이고 말할수록 더 큰 책임이 따른다.
- 사용자가 실제 사람이라고 착각할 수 있는 기술일수록 AI 생성 표기와 동의가 중요하다.
- 딥페이크를 막는 가장 좋은 방법은 탐지보다 예방이다.
- Mini PERSO AI는 지금까지 배운 조각들이 실제 서비스 구조로 합쳐지는 지점이다.
- 결국 AI 휴먼 프로젝트의 핵심은 기술 조립만이 아니라, 사용자가 믿고 쓸 수 있는 구조를 만드는 것이다.
