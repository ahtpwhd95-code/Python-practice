# 2026-05-18 SQL 고급 문법 복습 - 집합 연산, 재귀 CTE, 윈도우 함수

## 오늘 학습한 내용

### 1. UNION / UNION ALL
- `UNION`과 `UNION ALL`은 두 `SELECT` 결과를 위아래로 합칠 때 사용한다.
- `UNION ALL`은 중복을 제거하지 않고 모든 결과를 그대로 합친다.
- `UNION`은 두 결과를 합친 뒤 중복 데이터를 제거한다.
- 두 쿼리의 컬럼 개수와 순서가 같아야 한다.

```sql
SELECT name, number
FROM request_new
UNION ALL
SELECT name, number
FROM request_past;
```

```sql
SELECT name, number
FROM request_new
UNION
SELECT name, number
FROM request_past;
```

#### 이해한 방식
- `UNION ALL` : 다 가져와서 붙이기
- `UNION` : 붙인 뒤 중복 제거하기

---

### 2. INTERSECT / EXCEPT
- `INTERSECT`는 두 결과에 모두 존재하는 데이터만 조회한다.
- `EXCEPT`는 첫 번째 결과에는 있지만 두 번째 결과에는 없는 데이터를 조회한다.
- 수학의 교집합, 차집합과 비슷하게 이해할 수 있다.

```sql
SELECT name, email
FROM student
INTERSECT
SELECT name, email
FROM lecture_special;
```

```sql
SELECT student_number, student_name
FROM lecture_special
EXCEPT
SELECT student_number, student_name
FROM lecture_basic;
```

#### 이해한 방식
- `INTERSECT` : 양쪽에 모두 있는 데이터
- `EXCEPT` : 앞쪽에는 있고 뒤쪽에는 없는 데이터

---

### 3. WITH RECURSIVE
- `WITH RECURSIVE`는 계층형 데이터를 조회할 때 사용한다.
- 관리자-직원, 멘토-멘티처럼 위아래 관계가 있는 데이터를 단계별로 조회할 수 있다.
- 시작점과 반복 규칙으로 구성된다.

```sql
WITH RECURSIVE cte(member_id, manager_id, lvl) AS (
    SELECT member_id, manager_id, 0 AS lvl
    FROM `member`
    WHERE manager_id IS NULL

    UNION ALL

    SELECT a.member_id, a.manager_id, b.lvl + 1
    FROM `member` a
    JOIN cte b
    ON a.manager_id = b.member_id
)
SELECT member_id, manager_id, lvl
FROM cte
ORDER BY member_id, lvl;
```

#### 이해한 방식
- `manager_id IS NULL` : 최상위 관리자 찾기
- `lvl = 0` : 가장 위 계층
- `a.manager_id = b.member_id` : 현재 찾은 사람을 관리자로 가진 다음 계층 찾기
- `b.lvl + 1` : 한 단계 내려갈 때마다 계층 번호 증가

처음에는 CTE를 만들고 있는 중인데 자기 자신을 다시 조인하는 구조가 헷갈렸다.  
하지만 `cte`를 완성된 테이블이 아니라 **지금까지 찾은 중간 결과**라고 생각하니 이해가 쉬웠다.

---

### 4. 멘토 / 멘티 계층형 조회
- 관리자-직원 구조와 같은 방식으로 멘토-멘티 관계도 계층형으로 조회할 수 있다.
- 컬럼명만 다를 뿐 구조는 동일하다.

```sql
WITH RECURSIVE cte(mentee_id, mento_id, lvl) AS (
    SELECT mentee_id, mento_id, 0 AS lvl
    FROM `member`
    WHERE mento_id IS NULL

    UNION ALL

    SELECT a.mentee_id, a.mento_id, b.lvl + 1
    FROM `member` a
    JOIN cte b
    ON a.mento_id = b.mentee_id
)
SELECT mentee_id, mento_id, lvl
FROM cte
ORDER BY lvl, mentee_id;
```

#### 이해한 방식
- `mento_id IS NULL` : 최상위 멘토 찾기
- `a.mento_id = b.mentee_id` : a의 멘토가 b라면 a는 b의 아래 계층
- `lvl` : 몇 번째 계층인지 표시

컬럼명이 `member_id / manager_id`에서 `mentee_id / mento_id`로 바뀌니 처음에는 헷갈렸지만, 결국 핵심은 같았다.

> 상위 데이터를 먼저 찾고, 그 상위 데이터를 기준으로 아래 데이터를 반복해서 찾는다.

### 5. JOIN - ON / USING
- `JOIN`은 여러 테이블을 공통 기준으로 연결할 때 사용한다.
- `USING`은 양쪽 테이블의 컬럼명이 같을 때 짧게 사용할 수 있다.
- `ON`은 컬럼명이 다르거나 조건을 직접 작성해야 할 때 사용한다.

```sql
SELECT request_id, student_name
FROM class_request cr
INNER JOIN student s
USING(student_id);
```

위 쿼리는 아래와 같은 의미이다.

```sql
SELECT request_id, student_name
FROM class_request cr
INNER JOIN student s
ON cr.student_id = s.student_id;
```

컬럼명이 다를 때는 `ON`을 사용해야 한다.

```sql
SELECT rh.request_id, rh.req_status, m.member_name
FROM request_hist rh
INNER JOIN `member` m
ON rh.req_member_id = m.member_id
WHERE rh.req_status = 'fail';
```

#### 이해한 방식
- `ON` : 직접 조건을 쓰는 큰 범위
- `USING` : 같은 이름 컬럼끼리 조인할 때 쓰는 축약형

---

### 6. VIEW
- `VIEW`는 자주 사용하는 조회 결과를 가상의 테이블처럼 저장하는 기능이다.
- 실제 데이터를 새로 저장하는 것이 아니라, 조회 쿼리에 이름을 붙여두는 것에 가깝다.

```sql
CREATE VIEW employee_dev AS
SELECT employee_id, salary
FROM employee
WHERE department_name = '개발';
```

#### 오류 기록
```text
Table 'employee_dev' already exists
```

이미 같은 이름의 `VIEW` 또는 `TABLE`이 존재하면 생성할 수 없다.

### 7. 윈도우 함수
- 윈도우 함수는 기존 행을 유지하면서 계산 결과를 컬럼처럼 추가하는 함수이다.
- `GROUP BY`는 행을 묶어서 줄이지만, 윈도우 함수는 행을 줄이지 않는다.
- 순위, 누적 비율, 그룹 나누기, 전체 대비 비율 계산 등에 사용할 수 있다.

```sql
함수() OVER (
    PARTITION BY 그룹기준
    ORDER BY 정렬기준
)
```

#### 이해한 방식
- `GROUP BY` : 행을 묶어서 줄임
- `윈도우 함수` : 행은 그대로 두고 계산 결과만 옆에 붙임

---

### 8. RANK
- `RANK()`는 정렬 기준에 따라 순위를 매긴다.
- 같은 점수는 같은 순위로 처리한다.
- 동점자가 있으면 다음 순위는 건너뛴다.

```sql
SELECT
    MEMBER_ID,
    SQUAT,
    BENCH_PRESS,
    DEADLIFT,
    (SQUAT + BENCH_PRESS + DEADLIFT) AS WEIGHT_SUM,
    RANK() OVER (
        ORDER BY (SQUAT + BENCH_PRESS + DEADLIFT) DESC
    ) AS `RANK`
FROM GYM_MEMBER;
```

#### 이해한 방식
- `ORDER BY 총점 DESC` : 총점이 높은 순서대로 순위 부여
- `RANK()` : 동점자는 같은 순위
- 예시 : `1등, 2등, 2등, 4등`

---

### 9. SUM OVER
- `SUM() OVER()`는 전체 또는 그룹별 합계를 각 행 옆에 붙일 수 있다.
- `PARTITION BY`를 사용하면 특정 그룹별로 합계를 계산할 수 있다.

```sql
SELECT
    s.SELL_ID,
    s.SELLER_NAME,
    p.PRODUCT_NAME,
    s.QUANTITY,
    SUM(p.PRICE * s.QUANTITY) OVER (
        PARTITION BY s.SELLER_NAME, s.PRODUCT_ID
    ) AS `SUM_PRICE`
FROM sell s
INNER JOIN product p
ON s.PRODUCT_ID = p.PRODUCT_ID
ORDER BY s.SELL_ID;
```

#### 이해한 방식
- `PARTITION BY` : 계산할 그룹 기준
- `SUM(...) OVER(...)` : 행을 유지하면서 합계 컬럼 추가

---

### 10. 전체 대비 비율 계산
- `SUM() OVER()`를 사용하면 전체 합계를 각 행에서 사용할 수 있다.
- 이를 이용해 전체 대비 비율을 계산할 수 있다.

```sql
SELECT
    bu.ID,
    bu.USE_CODE,
    bu.EXPENSE,
    ROUND(100 * bu.EXPENSE / SUM(bu.EXPENSE) OVER(), 5) AS `ratio`
FROM budget_use bu
ORDER BY bu.ID;
```

#### 이해한 방식
- `SUM(bu.EXPENSE) OVER()` : 전체 지출 합계
- `현재 지출 / 전체 지출 * 100` : 전체 대비 비율

---

### 11. CUME_DIST
- `CUME_DIST()`는 정렬 기준에 따라 누적 백분율을 계산한다.
- 성적 상위 몇 퍼센트 위치인지 확인할 수 있다.

```sql
SELECT
    ID,
    SCORE,
    CUME_DIST() OVER(ORDER BY SCORE DESC) AS `CUME_DIST`
FROM STUDENT
ORDER BY ID;
```

#### 중요했던 점
`OVER` 안의 `ORDER BY`와 마지막 `ORDER BY`는 역할이 다르다.

```sql
CUME_DIST() OVER(ORDER BY SCORE DESC)
```

- 계산 기준

```sql
ORDER BY ID
```

- 최종 출력 순서

---

### 12. 윈도우 함수 결과에 조건 걸기
- 윈도우 함수 결과는 같은 `SELECT` 문의 `WHERE`에서 바로 사용할 수 없다.
- 먼저 서브쿼리에서 윈도우 함수 값을 계산한 뒤, 바깥 쿼리에서 조건을 걸어야 한다.

```sql
SELECT
    ID,
    SCORE,
    `CUME_DIST`
FROM (
    SELECT
        ID,
        SCORE,
        CUME_DIST() OVER(ORDER BY SCORE DESC) AS `CUME_DIST`
    FROM STUDENT
) S
WHERE `CUME_DIST` > 0.3
  AND `CUME_DIST` <= 0.7
ORDER BY `CUME_DIST`;
```

#### 이해한 방식
- 안쪽 쿼리 : 누적 백분율 계산
- 바깥 쿼리 : 계산된 값에 조건 적용

SQL 실행 순서상 `WHERE`가 `SELECT`보다 먼저 실행되기 때문에, 같은 단계에서 만든 별칭을 바로 사용할 수 없다.

---

### 13. NTILE
- `NTILE(n)`은 데이터를 정렬 기준에 따라 n개의 그룹으로 나눈다.
- 예를 들어 `NTILE(3)`은 데이터를 3개 그룹으로 나눈다.

```sql
SELECT
    ID,
    MATH,
    PHYSICS,
    CHEMISTRY,
    (MATH + PHYSICS + CHEMISTRY) AS SCORE_SUM,
    NTILE(3) OVER (
        ORDER BY (MATH + PHYSICS + CHEMISTRY) DESC
    ) AS `NTILE`
FROM student
ORDER BY ID;
```

#### 이해한 방식
- 총점 높은 순서대로 3개 그룹으로 나눈다.
- 1그룹은 상위권, 2그룹은 중위권, 3그룹은 하위권으로 볼 수 있다.
- 마지막 `ORDER BY ID`는 결과를 ID 순서로 보여주기 위한 것이다.

---

### 14. ROLLUP
- `ROLLUP`은 `GROUP BY` 결과에 중간 합계와 전체 합계를 추가로 출력한다.
- 결과에서 `NULL`은 실제 값이 아니라 합계를 의미할 수 있다.

```sql
SELECT
    bh.KIND,
    bh.CATEGORY,
    SUM(bh.SELL_COUNT)
FROM book_history bh
GROUP BY bh.CATEGORY, bh.KIND WITH ROLLUP;
```

#### 이해한 방식
- `CATEGORY = COOK, KIND = NULL` : COOK 카테고리 전체 합계
- `CATEGORY = NULL, KIND = NULL` : 전체 총합

- `NTILE()`을 이용한 그룹 나누기
- `GROUP BY ... WITH ROLLUP`을 이용한 중간 합계와 전체 합계 조회

## 핵심 정리
- `UNION ALL`은 중복 포함, `UNION`은 중복 제거 후 결과를 합친다.
- `INTERSECT`는 교집합, `EXCEPT`는 차집합처럼 이해할 수 있다.
- `WITH RECURSIVE`는 시작점과 반복 규칙으로 계층형 데이터를 조회한다.
- 재귀 CTE에서 자기 자신을 조인하는 이유는 지금까지 찾은 중간 결과를 기준으로 다음 계층을 찾기 위해서이다.
- `ON`은 직접 조인 조건을 작성하는 방식이고, `USING`은 같은 이름 컬럼끼리 연결할 때 쓰는 축약형이다.
- 윈도우 함수는 행을 줄이지 않고 계산 결과를 옆에 붙인다.
- `OVER` 안의 `ORDER BY`는 계산 기준이고, 마지막 `ORDER BY`는 출력 순서이다.
- 윈도우 함수 결과에 조건을 걸려면 서브쿼리로 한 번 감싸야 한다.
- `RANK()`는 동점자에게 같은 순위를 부여하고 다음 순위를 건너뛴다.
- `NTILE(n)`은 데이터를 n개의 그룹으로 나눈다.
- `ROLLUP`은 그룹별 합계뿐만 아니라 중간 합계와 전체 합계까지 출력한다.

## 오류 기록

### 1. 테이블명을 작은따옴표로 작성
```sql
FROM 'member'
```

작은따옴표는 문자열을 의미하기 때문에 테이블명에 사용할 수 없다.

올바른 작성:

```sql
FROM `member`
```

또는

```sql
FROM member
```

---

### 2. 재귀 CTE에서 SELECT * 사용
```sql
SELECT *, b.lvl + 1
```

재귀 CTE에서는 시작 SELECT와 반복 SELECT의 컬럼 개수와 순서가 같아야 한다.  
`SELECT *`를 사용하면 예상보다 많은 컬럼이 조회될 수 있으므로 명시적으로 컬럼을 작성해야 한다.

올바른 작성:

```sql
SELECT a.member_id, a.manager_id, b.lvl + 1
```

---

### 3. 함수 이름을 별칭으로 사용
```sql
NTILE(3) OVER (...) ntile
```

`NTILE`은 함수 이름이기 때문에 별칭으로 그대로 사용하면 오류가 발생할 수 있다.

해결:

```sql
NTILE(3) OVER (...) AS `NTILE`
```

또는 더 안전하게 다른 별칭을 사용한다.

```sql
NTILE(3) OVER (...) AS tile_group
```

## 느낀 점
- 오늘은 SQL 고급 문법이 한 번에 많이 나와서 어렵게 느껴졌다.
- `WITH RECURSIVE`는 처음에는 SQL 같지 않고 낯설었지만, 최상위 데이터를 먼저 찾고 그 아래 데이터를 반복해서 찾아가는 구조라고 생각하니 조금씩 이해가 되었다.
- 윈도우 함수도 처음에는 복잡했지만, `GROUP BY`처럼 행을 줄이는 것이 아니라 기존 행을 유지하면서 순위, 비율, 누적값을 붙이는 기능이라고 정리할 수 있었다.
- 오늘 발생한 오류들은 대부분 큰 로직이 틀렸다기보다, 작은따옴표, 별칭, 정렬 기준, 컬럼 개수처럼 세부 문법에서 발생했다.
- SQL은 단순 조회뿐만 아니라 데이터를 합치고, 연결하고, 계층 구조를 따라가고, 분석용 계산까지 할 수 있는 도구라는 것을 느꼈다.
- 완벽히 이해했다기보다는 직접 실행하고 오류를 고치면서 SQL 고급 문법의 흐름을 경험한 날이었다.
