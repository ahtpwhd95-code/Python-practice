## 오늘 배운 내용

### 1. 프롬프트, RAG, 파인튜닝의 차이

- 지금까지는 프롬프트로 모델에게 역할과 말투를 지시하고, RAG로 외부 지식을 참고하게 만들었다.
- 프롬프트는 빠르게 실험할 수 있지만 매번 길게 설명해야 하고, 대화가 길어지면 모델이 원래 말투로 돌아갈 수 있다.
- RAG는 최신 정보나 사내 문서처럼 외부 지식을 보강하는 데 적합하다.
- 파인튜닝은 모델의 일부 가중치를 직접 학습시켜 특정 말투, 성격, 출력 형식, 도메인 지식을 모델에 배게 만드는 방식이다.

| 방법 | 바꾸는 것 | 적합한 상황 |
|---|---|---|
| 프롬프트 | 입력 지시 | 빠른 실험, 일회성 지시 |
| RAG | 참고 지식 | 최신 정보, 사내 문서, 외부 지식 보강 |
| 파인튜닝 | 모델 가중치 일부 | 말투, 성격, 출력 형식, 도메인 구조 |
| 전체 파인튜닝 | 모델 전체 가중치 | 모델 능력 자체를 크게 변경 |

> 지식이 부족하면 RAG, 말투와 행동 패턴을 바꾸려면 파인튜닝이 적합하다.

### 2. LoRA의 핵심 원리

- LoRA는 거대한 모델 전체를 다시 학습하지 않고, 기존 가중치는 얼려 둔 채 작은 어댑터만 학습하는 방식이다.
- 원본 모델의 큰 가중치 행렬 `W`는 그대로 두고, 옆에 작은 두 행렬 `A`, `B`를 추가해 변화분만 학습한다.
- 학습 중에는 `A`, `B`만 업데이트하고, 추론 때는 `W + B·A` 형태로 사용한다.

```text
원본 가중치 W: 고정
LoRA 어댑터 A, B: 학습
추론 시 사용: W + B·A
```

| 개념 | 정리 |
|---|---|
| PEFT | Parameter-Efficient Fine-Tuning, 적은 파라미터만 학습하는 방식 |
| LoRA | 원본 모델은 고정하고 작은 어댑터만 학습하는 대표적인 PEFT 기법 |
| Low-rank | 큰 변화도 작은 행렬 두 개의 곱으로 근사할 수 있다는 아이디어 |
| Adapter | 특정 말투나 성격을 학습하는 작은 추가 가중치 |

- LoRA의 장점은 학습 파라미터가 적어 GPU 메모리, 시간, 저장 공간을 크게 줄일 수 있다는 점이다.
- 학습이 끝나면 전체 모델이 아니라 LoRA 어댑터만 저장할 수 있다.

### 3. QLoRA의 핵심 원리

- QLoRA는 LoRA에 양자화를 더한 방식이다.
- LoRA는 학습할 파라미터는 줄이지만, 고정된 원본 모델을 메모리에 올리는 부담은 여전히 크다.
- QLoRA는 원본 모델을 4bit로 양자화해 로드하고, 그 위에 LoRA 어댑터를 붙여 학습한다.
- 이를 통해 적은 GPU 메모리에서도 파인튜닝이 가능해진다.

| 구분 | LoRA | QLoRA |
|---|---|---|
| 원본 모델 | 일반 정밀도로 로드 | 4bit로 양자화해 로드 |
| 학습 대상 | LoRA 어댑터 | LoRA 어댑터 |
| 장점 | 학습 파라미터 감소 | 메모리 사용량까지 크게 감소 |
| 실습 적합성 | 중간 | 무료 Colab T4 환경에도 적합 |

> QLoRA는 개인 환경에서도 파인튜닝을 해볼 수 있게 만든 실용적인 기술이다.

### 4. LoraConfig 핵심 파라미터

LoRA를 사용할 때 중요한 설정은 크게 `r`, `lora_alpha`, `target_modules`이다.

| 파라미터 | 설명 |
|---|---|
| `r` | LoRA 어댑터의 rank. 높을수록 표현력은 좋아지지만 과적합 위험과 비용이 커진다 |
| `lora_alpha` | LoRA 변화분의 스케일. 보통 `r`의 2배 정도로 시작한다 |
| `target_modules` | LoRA 어댑터를 붙일 모델 내부 모듈 |
| `lora_dropout` | 과적합을 줄이기 위한 dropout |
| `task_type` | 학습 작업 유형. causal language model은 `CAUSAL_LM` |

```python
from peft import LoraConfig

cfg = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
```

실습에서는 보통 `r=16`, `lora_alpha=32`, `target_modules=["q_proj", "k_proj", "v_proj", "o_proj"]` 정도로 시작할 수 있다.

### 5. SFT와 페르소나 학습

- SFT는 Supervised Fine-Tuning의 약자이다.
- 정답 예시를 보여주며 모델이 그 패턴을 따라 하도록 학습시키는 방식이다.
- 페르소나 학습에서는 특정 말투와 성격으로 답하는 예시 데이터를 만든다.

```json
{
  "messages": [
    {
      "role": "system",
      "content": "너는 다정하고 차분한 상담 봇이야."
    },
    {
      "role": "user",
      "content": "오늘 기분이 별로야."
    },
    {
      "role": "assistant",
      "content": "그런 날엔 마음이 조금 무거울 수 있어요. 지금은 작은 일부터 천천히 해봐도 괜찮아요."
    }
  ]
}
```

좋은 파인튜닝 데이터 조건:

- 일관성: 같은 말투와 성격이 유지되어야 한다.
- 다양성: 여러 상황과 질문 유형이 포함되어야 한다.
- 품질: 많은 데이터보다 깔끔하고 일관된 데이터가 중요하다.
- 명확한 페르소나: 어떤 성격과 말투를 학습시킬지 분명해야 한다.

---

### 6. 과적합과 어댑터 저장

- 데이터가 적은 상태에서 너무 오래 학습하면 모델이 예시를 그대로 외우는 과적합이 발생할 수 있다.
- 과적합이 생기면 학습 데이터와 비슷한 질문에는 잘 답하지만, 새로운 질문에는 어색해질 수 있다.
- 답변이 반복적이거나 지나치게 정형화될 수 있다.
- loss가 지나치게 낮아져 거의 0에 가까워지는 것도 위험 신호가 될 수 있다.

과적합 대응 방법:

- `max_steps`를 작게 시작한다.
- 데이터 유형을 다양하게 만든다.
- dropout을 사용한다.
- 학습 전후 같은 질문 세트로 비교 평가한다.

어댑터 저장 방식:

| 방식 | 설명 |
|---|---|
| 어댑터만 저장 | 가볍게 저장하고 실행 시 베이스 모델에 붙여 사용 |
| merge 후 배포 | 베이스 모델과 어댑터를 합쳐 단일 모델처럼 배포 |
| 어댑터 교체 | 페르소나별 어댑터를 바꿔가며 여러 캐릭터 운영 |

### 7. DPO와 선호 정렬

- SFT는 지정한 모범 답안을 따라 하게 만드는 학습이다.
- 하지만 말투, 태도, 거절 방식처럼 정답 하나로 정의하기 어려운 문제는 SFT만으로 한계가 있다.
- DPO는 같은 질문에 대한 두 답변을 비교해 더 좋은 답변은 선호하고, 나쁜 답변은 피하도록 모델을 정렬한다.

| 구분 | SFT | DPO |
|---|---|---|
| 학습 방식 | 모범 답안을 따라 하게 함 | 좋은 답과 나쁜 답을 비교하게 함 |
| 데이터 형태 | `prompt + answer` | `prompt + chosen + rejected` |
| 적합한 것 | 말투, 형식, 기본 페르소나 학습 | 선호, 태도, 거절 방식, 답변 결 조정 |
| 비유 | 모범 답안 베껴 쓰기 | 둘 중 어떤 답이 더 나은지 알려주기 |

> SFT가 페르소나를 입히는 1차 작업이라면, DPO는 그 페르소나의 결을 더 정교하게 맞추는 작업이다.

---

### 8. 정렬의 의미

- 정렬은 모델이 단순히 맞는 답을 하는 것을 넘어, 사람이 원하는 방식으로 답하게 만드는 과정이다.
- 중요한 기준은 유용성, 정직성, 무해성, 페르소나 일관성이다.

| 기준 | 설명 |
|---|---|
| 유용성 | 사용자의 의도를 파악하고 실제로 도움이 되는 답변 |
| 정직성 | 모르면 모른다고 말하고 지어내지 않음 |
| 무해성 | 위험하거나 유해한 요청은 적절히 거절 |
| 페르소나 | 서비스가 원하는 말투와 성격을 일관되게 유지 |

---

### 9. 선호쌍 데이터 구조

- DPO 데이터는 정답 하나가 아니라 같은 질문에 대한 좋은 답변과 나쁜 답변의 쌍으로 구성된다.
- 필드는 `prompt`, `chosen`, `rejected`로 구성된다.

```json
{
  "prompt": "환불이 어렵다고 안내해줘.",
  "chosen": "죄송하지만 현재 규정상 환불은 어렵습니다. 대신 가능한 대안을 함께 안내드리겠습니다.",
  "rejected": "안 됩니다. 규정상 불가능합니다."
}
```

- DPO는 `chosen` 답변의 확률은 높이고, `rejected` 답변의 확률은 낮추는 방향으로 학습한다.
- 말투를 학습하려면 내용은 비슷하고 말투만 다르게 설계하는 것이 좋다.

---

### 10. RLHF와 DPO 비교

- RLHF는 사람의 선호 데이터를 바탕으로 보상 모델을 만들고, PPO 강화학습으로 모델을 조정하는 방식이다.
- 강력하지만 구조가 복잡하고 메모리와 비용이 많이 든다.
- DPO는 보상 모델 없이 선호쌍만으로 직접 모델을 최적화한다.
- 실습, 소규모 모델, 오픈소스 환경에서는 DPO가 더 실용적이다.

| 항목 | RLHF / PPO | DPO |
|---|---|---|
| 보상 모델 | 별도로 필요 | 필요 없음 |
| 필요한 모델 | 정책, 참조, 보상, 가치 모델 등 여러 개 | 학습 모델, 참조 모델 |
| 학습 방식 | 강화학습 기반 | 지도학습에 가까운 선호 최적화 |
| 난이도 | 높음 | 상대적으로 낮음 |
| 실습 적합성 | 낮음 | 높음 |

---

### 11. DPO 손실의 직관

- DPO는 참조 모델을 기준점으로 두고, 학습 중인 모델이 좋은 답변을 더 선호하고 나쁜 답변을 덜 선호하도록 만든다.
- `beta`는 참조 모델에서 얼마나 벗어날지 조절하는 값이다.

| beta | 의미 |
|---|---|
| 작음 | 보수적으로 변화하며 원본 모델에서 덜 벗어남 |
| 큼 | 더 강하게 정렬하지만 모델 성능 손상 위험 증가 |

보통은 `beta=0.1` 정도로 보수적으로 시작한다.

---

### 12. DPO로 AI 휴먼 페르소나 다듬기

DPO는 AI 휴먼의 말투, 태도, 거절 스타일을 정렬하는 데 사용할 수 있다.

| 목표 | chosen | rejected |
|---|---|---|
| 말투 일관성 | 친근하지만 정중한 말투 | 딱딱한 문어체 |
| 거절 스타일 | 이유와 대안을 함께 제시 | 단답형 거절 |
| 감정 톤 | 차분하고 따뜻한 반응 | 과한 감탄사와 이모지 |
| 서비스 페르소나 | 브랜드 톤 유지 | 일반 챗봇 같은 무색무취 답변 |

> DPO는 모델에게 “우리 서비스에는 이런 답변이 더 맞다”는 취향을 학습시키는 과정이다.

---

### 13. DPO 데이터 제작 시 주의점

- DPO 데이터 품질은 결과에 매우 민감하다.
- `chosen`과 `rejected`의 차이가 원하는 기준과 정확히 일치해야 한다.
- 말투를 학습하려면 내용은 비슷하고 말투만 달라지는 것이 좋다.
- 여러 기준이 동시에 흔들리면 모델이 무엇을 배워야 하는지 헷갈릴 수 있다.
- 라벨러의 기준과 편향이 모델에 그대로 반영될 수 있다.

주의할 문제:

| 문제 | 설명 |
|---|---|
| 라벨 노이즈 | 어떤 답이 좋은지 기준이 흔들리면 학습 방향이 흐려짐 |
| 과정렬 | `beta`가 너무 크거나 데이터가 편향되면 모델이 망가질 수 있음 |
| SFT 선행 필요 | 기본 말투와 능력이 부족하면 DPO만으로 해결하기 어려움 |
| 편향 주입 | 라벨러의 취향과 편향이 모델에 들어갈 수 있음 |

### 14. TRL DPOTrainer와 LoRA

- DPO 손실을 직접 구현하지 않아도 TRL의 `DPOTrainer`를 사용해 학습할 수 있다.
- LoRA와 4bit 모델을 함께 사용하면 작은 GPU 환경에서도 선호 정렬 실습이 가능하다.
- 데이터셋 컬럼은 `prompt`, `chosen`, `rejected` 형태로 맞춰야 한다.

```python
from trl import DPOTrainer, DPOConfig
from peft import LoraConfig

mid = "Qwen/Qwen2.5-1.5B-Instruct"

lora = LoraConfig(
    r=16,
    lora_alpha=32,
    task_type="CAUSAL_LM",
)

cfg = DPOConfig(
    beta=0.1,
    max_steps=60,
    learning_rate=5e-5,
)

trainer = DPOTrainer(
    model=model,
    args=cfg,
    train_dataset=pref_ds,
    peft_config=lora,
)

trainer.train()
```

## 오늘의 회고

### 배운 점

- 프롬프트, RAG, 파인튜닝은 서로 경쟁하는 방식이 아니라 각각 역할이 다른 도구라는 점을 이해했다.
- 프롬프트는 빠른 지시, RAG는 지식 보강, 파인튜닝은 말투와 성격을 모델에 입히는 데 적합하다.
- LoRA는 거대한 모델 전체를 학습하지 않고 작은 어댑터만 학습해 효율적으로 모델 행동을 바꾸는 방법이다.
- QLoRA는 원본 모델을 4bit로 양자화해 GPU 메모리 부담을 줄이고 개인 실습 환경에서도 파인튜닝을 가능하게 만든다.
- SFT는 모범 답안을 따라 하게 만드는 방식이고, DPO는 좋은 답과 나쁜 답을 비교해 선호를 정렬하는 방식이다.
- AI 휴먼을 만들 때는 지식보다도 어떤 말투와 태도로 답할지 정렬하는 과정이 중요하다는 점을 배웠다.

### 어려운 점 / 개선할 점

- LoRA와 QLoRA의 개념은 이해했지만 실제로 어떤 `target_modules`에 어댑터를 붙여야 하는지 더 감이 필요하다.
- `r`, `alpha`, `dropout`, `max_steps` 같은 하이퍼파라미터가 결과에 어떤 차이를 만드는지 직접 실험해봐야 할 것 같다.
- 파인튜닝 데이터는 양보다 품질이 중요하다는 점은 이해했지만, 좋은 페르소나 데이터를 만드는 기준을 더 연습해야 한다.
- DPO 데이터는 `chosen`과 `rejected`의 차이를 한 가지 기준으로 통제해야 하는데, 실제로는 말투, 내용, 길이가 동시에 달라지기 쉬워 설계가 어렵다.
- DPO는 강력하지만 라벨 기준이 흔들리면 모델을 이상하게 만들 수 있으므로 검증 과정이 꼭 필요하다.

---

## 액션 플랜

- Qwen2.5-1.5B 모델을 4bit로 로드하고 간단한 페르소나 데이터로 QLoRA 실습을 진행한다.
- 같은 질문을 학습 전과 학습 후에 물어 말투와 응답 형식이 어떻게 달라지는지 비교한다.
- 페르소나 데이터 10~30개를 직접 만들어보고 일관된 말투가 유지되는지 확인한다.
- DPO용 선호쌍 데이터를 직접 설계한다.
- `chosen`과 `rejected`는 내용보다 말투, 태도, 거절 방식 중 하나의 기준만 다르게 만들어본다.
- 학습 결과는 단순 감상이 아니라 같은 테스트 질문 세트로 비교 평가한다.
- 과적합 여부를 확인하기 위해 학습 데이터와 다른 새로운 질문도 함께 테스트한다.

---

## 함께 나누고 싶은 점

- 파인튜닝은 모델을 무조건 똑똑하게 만드는 작업보다, 특정 서비스에 맞는 말투와 행동 방식을 몸에 배게 만드는 작업에 가깝다.
- AI 휴먼에서는 지식보다도 페르소나의 일관성이 사용자 경험에 큰 영향을 줄 수 있다.
- LoRA와 QLoRA는 모델 전체를 다시 학습하지 않고도 작은 어댑터만으로 모델의 결을 바꿀 수 있다는 점에서 실용적이다.
- DPO는 우리가 원하는 답변과 피하고 싶은 답변의 차이를 모델에게 알려주는 방식이라, 서비스의 가치관과 응답 정책을 반영하는 데 유용하다.
- 다만 선호 데이터에는 라벨러의 기준과 편향이 들어갈 수 있으므로, 모델을 학습시키기 전에 데이터 기준을 명확히 세우는 것이 중요하다.

## 한 줄 정리

LoRA와 QLoRA는 작은 어댑터와 4bit 양자화로 파인튜닝 비용을 줄이고, DPO는 좋은 답과 피해야 할 답의 차이를 학습시켜 AI 휴먼의 말투와 태도를 서비스에 맞게 정렬하는 방법이다.
