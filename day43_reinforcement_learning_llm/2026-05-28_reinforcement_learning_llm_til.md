# 2026-05-28 TIL - 강화학습과 LLM 학습 흐름

## 오늘 학습한 내용

### 1. 강화학습 기본 개념

- 강화학습은 에이전트가 주어진 환경 안에서 시행착오를 반복하며, 보상의 합을 최대화하는 방향으로 학습하는 기법이다.
- 지도학습은 데이터와 정답을 함께 학습하고, 비지도학습은 데이터 안의 패턴을 스스로 찾는다.
- 강화학습은 행동의 결과로 받은 보상을 기준으로 더 나은 행동을 찾아간다.
- 강화학습은 단순히 AI가 알아서 똑똑해지는 과정이라기보다, 어떤 행동을 좋은 행동으로 볼 것인지 정의하고 반복적으로 개선하는 시스템 설계에 가깝다.

| 구성요소 | 의미 |
|---|---|
| Agent | 상태를 보고 행동을 선택하는 주체 |
| Environment | 에이전트와 상호작용하며 상태와 보상을 제공하는 대상 |
| State | 현재 환경에 대한 정보 |
| Action | 에이전트가 선택하는 동작 |
| Reward | 행동 결과로 얻는 평가값 |

---

### 2. 마르코프 결정 과정(MDP)

- 마르코프 결정 과정은 의사결정 문제를 수학적으로 표현하는 모델이다.
- 강화학습 문제를 설명할 때 자주 사용된다.
- MDP와 강화학습은 같은 개념이 아니며, MDP는 강화학습 문제를 표현하기 위한 수학적 틀에 가깝다.

| 구성요소 | 의미 |
|---|---|
| `S` | 가능한 상태의 집합 |
| `A` | 가능한 행동의 집합 |
| `P` | 전이 함수 |
| `R` | 보상 함수 |
| `γ` | 감가율 |

- 결정론적 환경은 같은 상태에서 같은 행동을 하면 항상 같은 다음 상태로 이동한다.
- 비결정론적 환경은 같은 행동을 해도 확률에 따라 다른 상태로 이동할 수 있다.
- 행동 가치 함수인 Q함수는 현재 상태에서 특정 행동을 했을 때 기대되는 누적 보상의 값을 나타낸다.

---

### 3. Q-Learning

- Q-Learning은 Q함수를 학습하여 더 좋은 행동 정책을 찾는 강화학습 알고리즘이다.
- Q-table은 각 상태에서 각 행동이 얼마나 좋은지를 저장하는 표이다.

```text
현재 상태 관찰
-> 행동 선택
-> 다음 상태와 보상 확인
-> 목표 Q값 계산
-> 기존 Q값과 목표값의 차이 계산
-> Q값 업데이트
```

- `np.argmax(Q[state, :])`는 가장 큰 값의 위치, 즉 선택할 행동을 구할 때 사용한다.
- `np.max(Q[next_state, :])`는 다음 상태에서 얻을 수 있는 가장 큰 Q값 자체를 구할 때 사용한다.
- 정리하면 `argmax`는 몇 번째 행동인지, `max`는 그 행동의 가치가 얼마인지 구할 때 사용한다.

---

### 4. Epsilon-Greedy

- Epsilon-Greedy는 탐험과 활용의 균형을 맞추기 위한 방법이다.
- 일정 확률 `epsilon`으로는 랜덤 행동을 선택하고, 나머지 확률로는 Q-table에서 가장 좋은 행동을 선택한다.
- 처음에는 환경을 잘 모르기 때문에 탐험이 중요하고, 학습이 진행될수록 탐험 비율을 줄이며 학습된 Q값을 더 많이 활용한다.

```python
epsilon = max(epsilon_end, epsilon * (1 - epsilon_decay))
epsilon = max(epsilon_end, epsilon - epsilon_decay)
```

- 비율로 감소하는 방식과 고정값으로 감소하는 방식이 있다.
- 실습 문제의 의도는 epsilon을 비율로 줄이는 방식에 더 가까웠다.

### 5. Taxi-v3와 FrozenLake 실습

- Taxi-v3 환경에서는 승객을 목적지에 내려주면 큰 보상을 받고, 일반 이동이나 잘못된 행동에는 패널티를 받는다.
- 학습 초기에는 에이전트가 좋은 행동과 나쁜 행동을 구분하지 못하기 때문에 reward가 매우 낮게 나올 수 있다.
- 학습이 진행되면서 좋은 행동의 Q값은 높아지고, 나쁜 행동의 Q값은 낮아지며 reward가 점차 개선된다.
- FrozenLake 실습에서는 4x4 환경을 8x8 환경으로 변경해보았다.
- 8x8 환경은 상태 수가 64개로 늘어나고, 경로가 길어지며 구멍도 많아져 탐험 전략이 더 중요해졌다.
- 같은 알고리즘이라도 환경 설정에 따라 난이도와 결과가 크게 달라진다는 점을 확인했다.

---

### 6. CartPole과 Policy Gradient / REINFORCE

- CartPole 환경에서는 REINFORCE 알고리즘을 사용했다.
- CartPole은 막대가 쓰러지지 않도록 왼쪽 또는 오른쪽으로 힘을 주는 문제이며, action은 이산형이다.
- 정책 모델은 현재 상태를 입력받아 각 행동을 선택할 확률을 출력한다.
- 이 확률을 Categorical 분포로 만들고, 그 분포에서 행동을 샘플링한다.
- 모델이 항상 가장 높은 확률의 행동만 선택하는 것이 아니라 확률적으로 행동을 선택하기 때문에 학습 중 점수가 출렁일 수 있다.

| action | 의미 |
|---|---|
| `0` | 왼쪽으로 밀기 |
| `1` | 오른쪽으로 밀기 |

- Gymnasium에서는 종료 조건이 `done`과 `truncated`로 나뉜다.
- `done`은 실패로 인한 종료이고, `truncated`는 시간 제한으로 인한 종료이다.
- `truncated`를 처리하지 않으면 CartPole-v1의 원래 최대 점수인 500점을 넘어 1000점, 3000점 이상까지 나올 수 있다.
- 정식 규칙을 따르려면 `done = done or truncated`처럼 처리해야 한다.
- 종료 조건 하나가 문제의 규칙 자체를 바꿀 수 있다는 점이 인상적이었다.

---

### 7. Pendulum-v1과 알고리즘의 한계

- Pendulum-v1은 CartPole과 달리 action이 연속값인 환경이다.
- 실습 코드에서는 action을 `[-1, 0, 1]` 세 개로 제한하고 Categorical 분포를 사용했다.
- 이는 연속 제어 문제를 억지로 이산 action 문제처럼 다루는 방식이기 때문에 학습이 잘 이루어지지 않았다.
- Pendulum처럼 연속적인 물리 제어 문제에는 PPO, DDPG, TD3, SAC 같은 알고리즘이 더 적합하다.
- 강화학습에서는 환경의 특성에 맞는 알고리즘 선택이 중요하다.

---

### 8. 알고리즘과 환경의 궁합

- 강화학습에서는 알고리즘 자체만 보는 것이 아니라, 상태 공간과 행동 공간의 특성을 함께 봐야 한다.
- Q-Learning은 작은 이산 상태/행동 문제에 적합하다.
- Policy Gradient / REINFORCE는 CartPole처럼 단순한 이산 action 환경에서 이해하기 좋다.
- Pendulum처럼 연속 action을 다루는 문제에는 다른 알고리즘이 더 적합하다.

강화학습 문제를 볼 때 먼저 확인할 질문:

- 상태 공간이 이산인가, 연속인가?
- 행동 공간이 이산인가, 연속인가?
- 보상이 자주 주어지는가, 희소한가?
- 환경이 결정론적인가, 비결정론적인가?
- 종료 조건은 무엇인가?

### 9. 로봇 제어와 Reward 설계

- CartPole과 Pendulum은 로봇 균형 제어 문제의 축소판처럼 볼 수 있다.
- 로봇 제어에서는 관절 각도, 각속도, 몸체 위치, 센서값 등이 state가 되고, 관절 토크나 모터 출력이 action이 된다.
- 현실에서는 바람, 마찰, 노면 상태, 센서 노이즈, 모터 지연 등 다양한 변수가 존재한다.
- 이런 변수를 반영하기 위해 시뮬레이션에서는 domain randomization을 사용할 수 있다.
- RC카 예시를 통해 reward 설계의 중요성을 이해했다.
- 단순히 목적지와 가까운 길이 항상 좋은 경로는 아니다.
- 거리가 조금 길어도 직선 주행으로 속도를 유지할 수 있다면 더 빠르게 도착할 수 있다.
- 강화학습에서 중요한 것은 모델 자체뿐 아니라 무엇을 잘한 행동으로 볼 것인지 정의하는 reward 설계이다.

### 10. LLM 학습과 강화학습의 연결

- 오후에는 강화학습 개념이 LLM 학습으로 연결되었다.
- LLM 학습 흐름은 사전학습, SFT/모방학습, Preference/RLHF/DPO로 정리할 수 있다.
- SFT는 질문과 모범답변을 보고 답변 형식을 따라 배우는 단계이다.
- Preference 데이터는 좋은 답변과 나쁜 답변을 비교하는 구조이다.
- RLHF나 DPO는 chosen 답변이 rejected 답변보다 더 선호되도록 모델을 조정하는 과정으로 볼 수 있다.
- CartPole에서 action이 왼쪽/오른쪽 행동이라면, LLM에서 action은 다음 토큰을 선택하는 것이다.
- CartPole에서 reward가 오래 버티는 점수라면, LLM에서 reward는 답변의 품질, 안전성, 선호도 등이 될 수 있다.

```text
사전학습 -> SFT / 모방학습 -> Preference / RLHF / DPO
```

Preference 데이터 구조:

```text
prompt   : 질문
chosen   : 더 좋은 답변
rejected : 더 나쁜 답변
```

### 11. SFT 데이터와 Preference 데이터 실습

- SFT 데이터는 `instruction`과 `output` 형태로 구성된다.
- KoAlpaca 데이터셋을 확인했을 때 컬럼은 `instruction`, `output`, `url`이었다.
- SFT에서는 instruction과 output을 하나의 텍스트로 합친 뒤 tokenizer를 사용해 숫자 토큰으로 변환한다.
- 모델은 자연어 문장을 직접 읽는 것이 아니라 `input_ids` 같은 숫자 토큰을 입력으로 받는다.
- Preference 데이터는 `chosen`과 `rejected`를 비교하는 구조이다.
- `maywell/ko_hh-rlhf-20k_filtered` 데이터셋은 별도의 prompt 컬럼 없이 chosen과 rejected 안에 전체 대화가 포함되어 있었다.
- Preference 데이터는 모델이 어떤 답변을 더 좋은 답변으로 선호해야 하는지 학습하는 데 사용된다.

### 12. KoAlpaca LoRA SFT 실습

- Colab에서 `Qwen/Qwen2.5-0.5B-Instruct` 모델을 베이스로 KoAlpaca 데이터셋을 사용해 LoRA SFT를 진행했다.
- 전체 약 4.95억 개 파라미터 중 학습 가능한 파라미터는 약 108만 개였고, 비율은 약 0.2184%였다.
- LoRA는 전체 모델을 모두 학습하지 않고 작은 어댑터만 학습하여 효율적으로 파인튜닝할 수 있다는 장점이 있다.
- 200 step 학습 결과 loss는 약 `2.57 -> 2.21`로 전체적으로 감소했다.
- 다만 loss가 줄었다고 해서 답변 품질이 바로 좋아지는 것은 아니었다.
- 가상환경 생성 질문에 대해 답변 형식은 좋아졌지만, 핵심 명령어는 정확하지 않았다.
- 짧은 SFT는 문체와 형식을 일부 모방할 수 있지만, 정확한 지식 답변을 안정적으로 생성하기에는 부족하다는 것을 확인했다.

### 13. DPO 실습 시도와 에러

- Preference 데이터로 DPO 실습도 시도했다.
- `trl` 라이브러리에서 `DPOConfig` import 문제가 발생했다.
- 설치된 라이브러리 버전과 강의 코드가 기대하는 API가 달라서 생긴 문제로 보였다.
- import 경로를 바꿔 일부 우회했지만, 이후 데이터셋 변수 정의 문제와 tensor dtype 관련 RuntimeError가 발생했다.
- DPO 학습은 완주하지 못했지만 RLHF 데이터셋 로드, chosen/rejected 구조 확인, DPO용 데이터셋 포맷 변환, DPOTrainer가 데이터셋을 처리하는 흐름은 확인했다.
- SFT보다 DPO 실습은 라이브러리 버전, tokenizer, chat template, tensor dtype에 더 민감하다는 것을 알게 되었다.

## 오늘의 회고

### 배운 점

- 강화학습은 환경, 상태, 행동, 보상, 종료 조건을 사람이 어떻게 설계하느냐에 따라 결과가 달라지는 시스템이다.
- Q-Learning에서는 `argmax`와 `max`의 차이를 명확히 이해했다.
- Epsilon-Greedy를 통해 탐험과 활용의 균형이 왜 중요한지 알게 되었다.
- CartPole 실습에서는 `truncated`를 처리하지 않으면 원래 문제의 규칙이 바뀔 수 있다는 것을 확인했다.
- Pendulum 실습을 통해 모든 환경에 같은 알고리즘을 적용할 수 없으며, 환경과 알고리즘의 궁합이 중요하다는 것을 알게 되었다.
- LLM 학습에서는 SFT, Preference, RLHF, DPO의 흐름을 배웠고, 강화학습 개념이 LLM의 답변 품질 개선과 연결된다는 것을 이해했다.
- LoRA SFT 실습을 통해 적은 파라미터만 학습해도 모델의 답변 형식이 일부 바뀔 수 있지만, 짧은 학습만으로 정확한 답변을 안정적으로 만들기는 어렵다는 것을 확인했다.

### 어려운 점 / 개선할 점

- 강화학습 코드는 `state`, `action`, `reward`, `next_state`, `done`, `truncated`가 반복적으로 등장해 흐름을 놓치기 쉬웠다.
- Policy Gradient와 REINFORCE에서는 확률적으로 행동을 샘플링하고 episode가 끝난 뒤 학습하는 흐름이 Q-Learning보다 직관적으로 느껴지지 않았다.
- SFT와 DPO 실습에서는 데이터셋 구조, tokenizer, 라이브러리 버전, tensor dtype 등 모델 학습 외적인 환경 문제가 결과에 큰 영향을 준다는 점이 어려웠다.
- DPO 실습은 완주하지 못했기 때문에 추후 라이브러리 버전과 데이터 포맷을 다시 맞춰볼 필요가 있다.
