# 2026-06-24 TIL - AI 휴먼의 얼굴과 LCEL·툴콜링

## 오늘 배운 내용

### 1. 아바타와 립싱크

- 디지털 휴먼은 크게 `LLM + TTS + 립싱크` 구조로 완성된다.
- LLM은 무엇을 말할지 정하는 두뇌 역할을 한다.
- TTS는 텍스트를 음성으로 바꾸는 성대 역할을 한다.
- 립싱크는 음성에 맞춰 얼굴과 입 모양을 움직이는 얼굴 근육 역할을 한다.
- 디지털 휴먼은 단순한 챗봇이 아니라 답변 생성, 음성 합성, 말하는 얼굴 영상 생성까지 이어지는 멀티모달 서비스라고 볼 수 있다.

```text
사용자 질문 -> LLM 답변 생성 -> TTS 음성 합성 -> 립싱크 영상 생성 -> AI 휴먼 응답
```

---

### 2. 말하는 얼굴을 만드는 주요 방식

- Wav2Lip은 영상 또는 사진과 음성을 입력받아 입술 움직임을 음성에 맞게 다시 그리는 방식이다.
- SadTalker는 사진 한 장과 음성만으로 입, 머리 움직임, 표정까지 생성할 수 있다.
- 3D·디퓨전 방식은 NeRF, 3DGS, 디퓨전 등을 활용해 더 고품질의 얼굴 움직임을 만들 수 있다.
- 3D·디퓨전 방식은 품질은 높을 수 있지만 비용과 구현 난이도가 높다.
- PERSO, HeyGen, D-ID 같은 상용 API는 API 호출만으로 말하는 영상을 만들 수 있어 빠르다.
- 상용 API는 구현은 쉽지만 비용과 외부 의존성 문제가 있다.

---

### 3. Wav2Lip의 핵심 원리

- Wav2Lip은 음성 파형을 짧은 구간으로 나누고, 멜 스펙트로그램 같은 음향 특징을 분석한다.
- 이후 신경망이 소리와 입 모양의 대응 관계를 추론한다.
- 프레임마다 입 영역을 음성에 맞게 다시 생성한다.
- 기존 얼굴 전체를 바꾸는 것이 아니라, 주로 입 주변 영역을 음성에 맞게 재생성한다는 점이 핵심이다.

```text
얼굴 영상/사진 + 음성 wav -> 음향 특징 추출 -> 입 영역 생성 -> 립싱크 영상
```

---

### 4. 사전렌더와 실시간 생성

- 사전렌더는 대사가 정해져 있을 때 미리 영상을 만들어두는 방식이다.
- 사전렌더는 재생 시 지연이 거의 없고 품질을 높일 수 있다.
- 실시간 생성은 사용자 입력에 따라 즉시 음성과 영상을 생성하는 방식이다.
- 실시간 생성은 대화형 서비스에 적합하지만 지연 시간과 GPU 비용이 문제다.
- 실전에서는 자주 쓰는 안내 문구는 사전렌더로 캐싱하고, 사용자별 동적 답변만 실시간으로 생성하는 하이브리드 방식이 적합하다.

---

### 5. 디지털 휴먼 윤리

- 립싱크와 talking-head 기술은 누구나 말하게 만들 수 있다는 강력한 장점이 있다.
- 동시에 딥페이크와 사칭 위험도 크다.
- 타인의 얼굴이나 목소리를 사용할 때는 반드시 명시적 동의가 필요하다.
- 생성물에는 AI 생성 여부를 표시하고, 사용 범위를 명확히 해야 한다.
- 동의 없는 실존 인물 합성이나 오해를 부르는 무표기 배포는 피해야 한다.

---

### 6. LCEL의 개념

- LCEL은 LangChain Expression Language의 약자이다.
- `prompt`, `llm`, `parser` 같은 부품을 `|` 파이프로 연결해 체인을 만드는 방식이다.
- 모든 부품은 Runnable 규격을 따른다.
- Runnable은 `invoke`, `batch`, `stream` 같은 공통 실행 방식을 가진다.
- 체인도 다시 Runnable이 되기 때문에 여러 부품을 레고처럼 조립하고 재사용할 수 있다.

```python
chain = prompt | llm | parser
result = chain.invoke({"question": "LCEL이 뭐야?"})
```

---

### 7. LCEL 실행 방식

- `invoke`는 입력 하나를 받아 결과 하나를 반환하는 기본 실행 방식이다.
- `batch`는 여러 입력을 한 번에 처리할 때 사용한다.
- `batch`는 평가셋 테스트나 대량 처리에 적합하다.
- `stream`은 결과를 토큰 단위로 조금씩 받아오는 방식이다.
- `stream`은 챗봇이나 AI 휴먼 서비스에서 체감 속도를 높이는 데 중요하다.

---

### 8. Runnable 활용

- `RunnableParallel`은 같은 입력을 여러 체인에 동시에 넣고 결과를 딕셔너리 형태로 묶는다.
- `RunnablePassthrough`는 원본 입력을 유지하면서 새 값을 추가할 때 사용한다.
- `RunnableLambda`는 일반 파이썬 함수를 LCEL 체인 안에 넣을 수 있도록 감싸는 역할을 한다.
- `RunnableBranch`는 조건에 따라 다른 체인으로 분기하는 라우팅 구조를 만들 때 사용한다.

---

### 9. 구조화 출력

- LLM의 줄글 답변은 코드에서 안정적으로 분기하기 어렵다.
- 따라서 감정, 의도, 키워드처럼 필요한 값을 JSON 또는 Pydantic 객체 형태로 받아야 한다.
- Pydantic `BaseModel`로 원하는 출력 모양을 선언할 수 있다.
- 파서가 만든 format instructions를 프롬프트에 넣으면 안정적인 구조화 출력이 가능하다.
- 구조화 출력은 감정 분석, 의도 분류, 라우팅, 후속 처리에 매우 중요하다.

---

### 10. 파서 실패 대비

- 로컬 모델은 JSON만 출력하지 않고 "물론이죠" 같은 군더더기를 붙일 수 있다.
- 따라서 파서 실패를 대비해 3단 방어가 필요하다.
- 1단계는 파서로 그대로 처리하는 것이다.
- 2단계는 정규식으로 `{}` JSON 영역만 추출하는 것이다.
- 3단계는 그래도 실패하면 안전한 기본값을 반환하는 것이다.
- 구조화 출력이나 툴 콜링에서는 `temperature`를 0.0~0.3 정도로 낮춰 형식을 안정화하는 것이 좋다.

---

### 11. 툴 콜링과 ReAct 루프

- LLM은 실제 날씨, 계산, 환율 같은 외부 정보를 직접 처리하기 어렵다.
- LLM은 어떤 도구를 어떤 인자로 호출할지 판단한다.
- 실제 실행은 파이썬 함수가 담당한다.
- 툴 콜링은 도구 선택, 함수 실행, 결과 재투입, 최종 답변 생성 흐름으로 동작한다.
- 이 흐름이 Reasoning과 Acting을 반복하는 ReAct 패턴의 기본 구조다.

```text
질문 -> 도구 선택 -> 함수 실행 -> 결과 재투입 -> 최종 답변
```

---

### 12. 로컬 모델에서의 실전 방식

- 로컬 모델은 `bind_tools`나 `with_structured_output` 같은 native 기능이 모델·래퍼 버전에 따라 불안정할 수 있다.
- 따라서 로컬에서는 도구 설명과 출력 형식을 프롬프트에 명확히 적는 방식이 더 안정적이다.
- 모델이 JSON으로 답하게 한 뒤 파서로 처리하는 구조를 사용할 수 있다.
- 구조화 출력에서 배운 프롬프트와 파서 방식이 툴 콜링에도 그대로 재사용된다.

## 오늘의 회고

### 배운 점

- AI 휴먼은 단순히 LLM 하나로 완성되는 것이 아니라, LLM이 말할 내용을 만들고 TTS가 목소리를 만들며 립싱크가 얼굴을 움직이는 구조라는 점을 이해했다.
- Wav2Lip, SadTalker, 3D·디퓨전, 상용 API는 각각 입력 방식, 품질, 비용, 구현 난이도가 다르기 때문에 서비스 목적에 따라 선택해야 한다.
- LCEL은 LLM 체인을 단순히 코드로 길게 짜는 것이 아니라, prompt, model, parser, function을 Runnable 단위로 조립하는 방식이라는 점이 인상적이었다.
- 구조화 출력이 중요한 이유는 LLM 결과를 사람이 읽는 답변이 아니라, 코드가 안정적으로 처리할 수 있는 데이터로 바꾸기 위해서라는 점을 배웠다.

### 어려운 점 / 개선할 점

- Wav2Lip 같은 립싱크 모델은 개념은 직관적이지만 설치와 실행 환경이 까다로울 수 있어 버전 관리가 중요해 보인다.
- LCEL은 개념이 많아 `RunnableParallel`, `RunnablePassthrough`, `RunnableLambda`, `RunnableBranch`의 차이를 실제 코드로 반복해서 익혀야 할 것 같다.
- 구조화 출력과 툴 콜링은 파서 실패, JSON 깨짐, 잘못된 도구 선택 같은 예외 처리가 핵심이라 단순 구현보다 방어 로직이 중요하다.

## 액션 플랜

- Wav2Lip 실습에서는 얼굴 입력, 음성 wav, 출력 mp4 흐름을 직접 확인해본다.
- LCEL 실습에서는 `prompt | llm | parser` 기본 체인을 먼저 만든다.
- 이후 `RunnableParallel`, `RunnablePassthrough`, `RunnableLambda`, `RunnableBranch`를 하나씩 추가해본다.
- Pydantic 구조화 출력 예제를 만들어 의도, 감정, 키워드를 JSON 형태로 안정적으로 받는 연습을 한다.
- 툴 콜링은 날씨조회, 계산기, 환율조회 같은 간단한 예시로 수동 ReAct 루프를 구현해본다.

## 함께 나누고 싶은 점

- AI 휴먼을 만들 때 기술 구현만큼 중요한 것은 윤리와 동의 문제다.
- 얼굴과 목소리는 개인의 정체성과 연결되기 때문에, 실존 인물 데이터를 사용할 때는 반드시 동의와 사용 범위를 명확히 해야 한다.
- 서비스에서는 실시간 생성만 고집하기보다, 자주 쓰는 문구는 사전렌더로 캐싱하고 동적 응답만 실시간으로 처리하는 하이브리드 구조가 현실적이라고 느꼈다.
