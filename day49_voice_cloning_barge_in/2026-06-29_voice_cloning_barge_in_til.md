# 2026-06-29 TIL - 음성 클로닝·감정 TTS와 실시간 대화 Barge-in

## 오늘 배운 내용

### 1. 음성 클로닝과 감정 TTS

- 이전 수업에서는 STT로 듣고, TTS로 말하는 기본 음성 루프를 만들었다.
- 기본 TTS는 모델에 미리 들어 있는 고정 화자의 목소리를 사용하는 경우가 많다.
- 이번 수업에서는 약 30초 정도의 참조 음성 샘플을 이용해 특정 사람의 목소리를 복제하고, 그 목소리로 문장을 합성하는 방법을 배웠다.
- 음성 클로닝은 단순히 소리를 흉내 내는 것이 아니라, 목소리의 톤, 억양, 말투 특징을 speaker embedding으로 추출해 TTS 생성 조건으로 사용하는 구조이다.

| 개념 | 정리 |
|---|---|
| 음성 클로닝 | 짧은 참조 음성으로 특정 화자의 목소리를 따라 하는 TTS 기술 |
| Speaker Embedding | 목소리의 음색, 억양, 말투 특징을 숫자 벡터로 압축한 표현 |
| Zero-shot Cloning | 별도 학습 없이 샘플 음성 하나만으로 즉시 목소리를 복제하는 방식 |
| Fine-tuning | 특정 화자의 음성을 많이 모아 모델을 다시 학습시키는 방식 |
| 감정 TTS | 같은 목소리에 기쁨, 슬픔, 차분함 같은 감정과 스타일을 입히는 기술 |

---

### 2. 음성 클로닝 흐름

1. 참조 음성 샘플을 입력한다.
2. 모델이 목소리 특징을 speaker embedding으로 추출한다.
3. 합성할 텍스트를 입력한다.
4. 텍스트 내용과 speaker embedding을 결합해 해당 화자처럼 들리는 음성을 생성한다.

```text
참조 음성 -> speaker embedding 추출
텍스트 + speaker embedding -> cloned TTS 음성 생성
```

텍스트는 "무엇을 말할지"를 정하고, speaker embedding은 "누구 목소리로 말할지"를 정한다.

### 3. XTTS-v2와 OpenVoice v2 비교

| 모델 | 방식 | 장점 | 특징 |
|---|---|---|---|
| XTTS-v2 | Zero-shot cloning + TTS 통합 | 사용이 간단하고 한국어 실습에 적합 | 참조 음성과 텍스트만 넣으면 바로 합성 가능 |
| OpenVoice v2 | 기본 음성 생성 후 voice conversion | 감정, 억양, 속도 제어가 더 유연함 | 음색 변환과 스타일 조절에 유리 |
| YourTTS | XTTS 이전 계열 zero-shot 모델 | 비교적 가볍고 빠름 | 한국어 지원은 제한적 |
| F5-TTS | 최신 zero-shot 계열 | 자연스러운 합성 품질 | 한국어는 추가 모델이 필요할 수 있음 |

- 빠르게 한국어 목소리 복제를 실습하려면 XTTS-v2가 적합하다.
- 감정, 억양, 악센트, 속도를 더 세밀하게 제어하려면 OpenVoice v2 구조가 유리하다.

### 4. 감정이 담긴 목소리 만들기

- 음성 클로닝은 목소리를 복제하는 것에서 끝나지 않는다.
- 실제 사람처럼 들리려면 목소리에 감정과 스타일이 들어가야 한다.
- 감정 TTS에서는 모델 자체보다 참조 음성의 품질과 감정 표현이 중요하다.

| 요소 | 설명 |
|---|---|
| 감정 참조 음성 | 밝은 목소리로 녹음하면 결과도 밝아질 가능성이 높다 |
| 말의 속도 | 빠르거나 느린 속도로 말투 분위기를 바꿀 수 있다 |
| 억양 | 말끝 상승, 피치 변화, 강세가 감정 표현에 영향을 준다 |
| 톤 | 차분한 참조 음성은 차분한 결과를, 밝은 참조 음성은 밝은 결과를 만든다 |

> 원하는 감정으로 녹음한 참조 음성 자체가 일종의 연출 프롬프트가 된다.

### 5. 크로스링구얼 음성 클로닝

- 크로스링구얼 음성 클로닝은 한 언어로 녹음한 목소리를 다른 언어 발화에 적용하는 기술이다.
- 예를 들어 한국어로 녹음한 30초 음성을 참조로 사용하고, 영어 문장을 입력하면 같은 목소리로 영어를 말하는 음성을 만들 수 있다.

활용 예시:

- 내 목소리로 외국어 안내 음성 제작
- 브랜드 성우 목소리로 다국어 콘텐츠 제작
- 외국어 더빙을 본인 목소리처럼 생성
- AI 휴먼이 같은 페르소나로 여러 언어를 말하게 만들기

---

### 6. 음성 클로닝의 윤리와 책임

- 목소리는 단순한 소리가 아니라 개인의 생체정보와 정체성에 가까운 정보이다.
- 기술적으로 가능하더라도 아무 목소리나 복제해서는 안 된다.
- 보이스피싱, 사칭, 동의 없는 복제, 라이선스 위반 위험이 있다.
- 합성 음성임을 표시하거나 고지하는 투명성이 필요하다.

실습 원칙:

- 본인 목소리 또는 명시적으로 동의받은 목소리만 사용한다.
- 유명인, 강사, 유튜버 등의 목소리를 무단으로 복제하지 않는다.
- 결과물을 공유할 때는 AI 합성 음성임을 밝힌다.
- 상업 사용 전에는 모델 라이선스와 데이터 사용 조건을 확인한다.

### 7. 실시간 대화와 Barge-in

- 이전 구조는 `STT -> LLM -> TTS` 흐름으로 동작하는 순차적 음성 챗봇에 가까웠다.
- 순차적 구조에서는 사용자가 말하고, AI가 말하고, 다시 사용자가 말하는 식으로 차례를 기다려야 한다.
- 이번 수업에서는 사람이 AI의 말을 중간에 끊으면 AI가 즉시 멈추는 실시간 대화 구조를 배웠다.
- 이를 Barge-in이라고 한다.

| 개념 | 정리 |
|---|---|
| VAD | 사용자가 말하고 있는지 감지하는 Voice Activity Detection |
| Barge-in | AI가 말하는 중 사용자가 끼어들면 AI 발화를 멈추는 기능 |
| Turn-taking | 지금 말할 차례가 사용자에게 있는지 AI에게 있는지 관리하는 구조 |
| 지연 예산 | STT, LLM, TTS 각 단계의 지연 시간을 합산해 체감 속도를 설계하는 것 |
| AEC | 스피커에서 나온 AI 목소리가 마이크로 다시 들어가는 에코를 제거하는 기술 |

---

### 8. 반실시간 대화와 진짜 실시간 대화

| 구분 | 반실시간 대화 | 진짜 실시간 대화 |
|---|---|---|
| 방식 | 한 명이 말하고 끝나면 다음 사람이 말함 | 듣기와 말하기가 동시에 진행됨 |
| 말끝 판단 | 버튼, 엔터, 녹음 종료 등으로 판단 | VAD가 자동으로 말끝을 감지 |
| 끼어들기 | 불가능 | 가능 |
| 체감 | 무전기처럼 순차적 | 전화 통화처럼 자연스러움 |
| 핵심 기술 | STT, LLM, TTS | STT, LLM, TTS, VAD, Barge-in |

---

### 9. VAD의 역할

- VAD는 Voice Activity Detection의 약자이다.
- 오디오 청크마다 말소리인지 침묵인지 판단한다.
- 말소리가 일정 시간 지속되면 말 시작으로 판단한다.
- 침묵이 일정 시간 지속되면 말 끝으로 판단한다.
- 말 끝이 감지되면 STT로 넘겨 텍스트를 만든다.
- AI가 말하는 중 사용자 음성이 감지되면 barge-in 신호로 사용할 수 있다.

VAD가 필요한 이유:

- 버튼 없이 자동으로 말 시작과 끝을 판단할 수 있다.
- 침묵 구간에는 STT를 돌리지 않아 비용을 줄일 수 있다.
- 사용자가 AI 발화 중 끼어드는 순간을 감지할 수 있다.

---

### 10. Barge-in 동작 구조

- AI가 TTS로 답변을 재생한다.
- 동시에 VAD가 계속 마이크 입력을 감지한다.
- 사용자 말소리가 감지되면 `stop_flag`가 켜진다.
- LLM 생성 루프 또는 TTS 재생 루프가 `stop_flag`를 확인하고 즉시 중단한다.
- 발화 차례가 다시 사용자에게 넘어간다.

```python
if vad_detects_speech(mic_chunk):
    stop_flag.set()

for sentence in llm_stream:
    if stop_flag.is_set():
        break
```

핵심은 중단 플래그 하나다. 사용자가 말하면 `stop_flag`를 켜고, AI는 그 신호를 보고 바로 멈춘다.

---

### 11. 실시간 대화 구현의 어려움

| 문제 | 설명 | 해결 방향 |
|---|---|---|
| 잘못된 끼어들기 | 기침, 웃음, 짧은 맞장구에도 AI가 멈출 수 있음 | 최소 발화 길이와 임계값 조정 |
| VAD 오판 | 소음을 말소리로 보거나 작은 목소리를 침묵으로 볼 수 있음 | 환경별 튜닝 필요 |
| 지연 누적 | STT, LLM, TTS 시간이 쌓이면 응답이 느려짐 | 스트리밍, 문장 단위 TTS, 병렬 처리 |
| 에코 루프 | AI 목소리가 마이크에 다시 들어가 자기 말을 듣는 문제가 생김 | 헤드셋, AEC, 입력 게이팅 |

### 12. 전체 아키텍처

실시간 대화형 AI 휴먼은 크게 듣기 루프와 말하기 루프로 구성된다.

#### 듣기 루프

- 마이크 입력을 계속 받는다.
- VAD로 말 시작과 말 끝을 감지한다.
- 사용자 말이 끝나면 STT로 텍스트화한다.
- AI가 말하는 중 사용자 음성이 감지되면 `stop_flag`를 켠다.

#### 말하기 루프

- LLM이 답변을 스트리밍으로 생성한다.
- 문장이 완성되면 바로 TTS로 합성한다.
- 앞 문장을 재생하는 동안 다음 문장을 미리 준비한다.
- 매 문장마다 `stop_flag`를 확인하고, 사용자가 끼어들면 즉시 멈춘다.

```text
듣기 루프: mic -> VAD -> STT -> user text / stop_flag
말하기 루프: LLM stream -> sentence buffer -> TTS -> playback
```

## 오늘의 회고

### 배운 점

- 음성 클로닝은 단순히 소리를 흉내 내는 것이 아니라, 참조 음성에서 화자 특징을 speaker embedding으로 추출하고 이를 텍스트 합성 과정의 조건으로 넣는 구조라는 점을 이해했다.
- Zero-shot cloning은 짧은 샘플만으로 즉시 목소리를 복제할 수 있어 실습과 프로토타입 제작에 강점이 있다.
- 감정 TTS에서는 모델보다 참조 음성의 톤, 감정, 억양, 속도가 결과에 큰 영향을 준다는 점을 알게 되었다.
- 실시간 대화에서는 단순히 STT, LLM, TTS를 연결하는 것만으로는 부족하고 VAD, Barge-in, turn-taking, echo 처리까지 고려해야 한다.
- AI 휴먼이 자연스럽게 느껴지려면 잘 말하는 것뿐 아니라 언제 멈추고, 언제 듣고, 언제 다시 말할지를 설계해야 한다.

### 어려운 점 / 개선할 점

- 밝고 감정이 담긴 목소리를 직접 녹음하는 것이 생각보다 어렵다.
- 단순히 읽는 것이 아니라 피치, 억양, 말끝, 속도까지 조절해야 한다.
- 음성 클로닝 결과가 자연스럽게 나오려면 참조 음성의 길이, 품질, 잡음, 감정 상태가 모두 중요하다.
- Barge-in 구조는 개념은 단순하지만 실제 서비스에서는 에코, 소음, VAD 오판 때문에 튜닝이 많이 필요할 것 같다.
- 실시간 대화는 각 단계의 지연 시간이 조금만 늘어나도 체감 품질이 크게 떨어지기 때문에 지연 예산을 설계하는 감각이 필요하다.
